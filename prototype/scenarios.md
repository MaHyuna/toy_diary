# 몽글 전체 시나리오 명세 · 2026-11-06

16개 업무 흐름, 142개 화면. 기존 구현과 확장 설계를 함께 다룹니다. 확장 화면은 실제 결제·인증·메시지·복원을 수행하지 않습니다.

## 예약 상태와 금액 원칙

예약: 결제 전 → 예약금 확인 → 검토 대기 → 확정 또는 변경 요청 → 고객 재선택 → 재검토(반복). 거절·취소 사유를 보존합니다. 확정 후 변경도 재검토를 거칩니다.

결제: 요청/확인 중/성공/실패, 환불: 요청/확인 중/완료/실패를 별도 관리합니다. 결제 응답이 불명확하면 조회하고 중복 청구하지 않습니다. 총액에서 이미 받은 예약금을 차감합니다. 같은 금액의 일정 변경에는 중복 예약금을 받지 않습니다.

## 운영 전 결정할 정책

- 예약금 금액·정액/비율·예외, 서비스 조합·소요시간, 임시 시간 점유와 만료 기한
- 무료 취소 기한·귀책별 환불·노쇼, 변경 시 금액 차이와 부분 환불
- 미응답 처리·고객 답변 기한·제안 중 원일정 점유 방식
- 필수/선택 개인정보·사진 동의, 탈퇴·거래 보존, 고객 기록 연결 승인
- 결제 PG·알림 제공자·공식 외부 예약 연동 범위, 백업 주기·복구 목표·승인

## 고객 시나리오

### 회원가입·로그인·계정 복구

가입, 휴대폰 확인, 약관 동의부터 로그인 복구와 탈퇴까지.

- **가입·로그인 선택** (고객 · 진입 · 확장 설계)
  - 목적: 처음 온 고객과 기존 고객의 경로를 나눕니다.
  - 규칙: 소셜 로그인 제공자는 별도 결정합니다.
  - 이동: 회원가입 → 회원가입 정보·동의 / 기존 계정 로그인 → 고객 로그인
- **회원가입 정보·동의** (고객 · 등록 · 확장 설계)
  - 목적: 최소 정보와 필수 약관을 확인합니다.
  - 규칙: 마케팅 동의는 선택입니다. 기존 번호가 있으면 로그인·복구로 연결합니다.
  - 이동: 본인 확인 → 휴대폰 확인 / 이미 가입된 번호 → 기존 계정 안내
- **휴대폰 확인** (고객 · 확인 · 확장 설계)
  - 목적: 인증번호를 입력합니다.
  - 규칙: 인증 실패·유효시간 만료·재전송 제한을 표시합니다.
  - 이동: 인증 성공 → 가입 완료·첫 반려동물 안내 / 인증번호 만료 → 인증 만료·실패
- **인증 만료·실패** (고객 · 예외 · 확장 설계)
  - 목적: 원인을 알리고 다시 시도합니다.
  - 규칙: 가입을 완료 처리하지 않습니다.
  - 이동: 번호 재전송 → 휴대폰 확인 / 번호 수정 → 회원가입 정보·동의
- **기존 계정 안내** (고객 · 예외 · 확장 설계)
  - 목적: 같은 휴대폰으로 중복 가입하지 않습니다.
  - 규칙: 계정 존재 여부 노출은 인증 후로 제한합니다.
  - 이동: 기존 계정 로그인 → 고객 로그인 / 계정 복구 → 계정 복구·재인증
- **가입 완료·첫 반려동물 안내** (고객 · 결과 · 확장 설계)
  - 목적: 가입 후 반려동물 등록을 안내합니다.
  - 규칙: 반려동물 미등록 상태에서도 요금표·공지 조회는 가능합니다.
  - 이동: 로그인된 홈 → 로그인된 고객 홈
- **고객 로그인** (고객 · 인증 · 확장 설계)
  - 목적: 기존 계정으로 로그인합니다.
  - 규칙: 고객 세션은 사장님 권한을 부여하지 않습니다.
  - 이동: 로그인 성공 → 로그인된 고객 홈 / 비밀번호 찾기 → 계정 복구·재인증 / 로그인 실패 → 로그인 실패·시도 제한
- **로그인 실패·시도 제한** (고객 · 예외 · 확장 설계)
  - 목적: 실패 안내와 복구 경로를 제공합니다.
  - 규칙: 반복 실패는 잠시 제한합니다.
  - 이동: 다시 로그인 → 고객 로그인 / 계정 복구 → 계정 복구·재인증
- **계정 복구·재인증** (고객 · 확인 · 확장 설계)
  - 목적: 본인 확인 후 로그인 수단을 재설정합니다.
  - 규칙: 연결된 반려동물과 예약 이력은 유지합니다.
  - 이동: 재인증 성공 → 고객 로그인 / 인증 실패 → 인증 만료·실패
- **로그인된 고객 홈** (고객 · 조회 · 확장 설계)
  - 목적: 반려동물·최근 예약·기록을 확인합니다.
  - 규칙: 세션 만료 시 재로그인 후 원래 화면으로 돌아갑니다.
  - 이동: 로그아웃 → 가입·로그인 선택 / 회원 탈퇴 검토 → 탈퇴·보존 내역 확인
- **탈퇴·보존 내역 확인** (고객 · 확인 · 확장 설계)
  - 목적: 진행 중 예약과 환불을 먼저 안내합니다.
  - 규칙: 탈퇴와 법정 보존 기록 삭제는 다릅니다. 진행 중 거래 정리와 보존 정책 확정이 필요합니다.
  - 이동: 진행 중 예약으로 탈퇴 보류 → 로그인된 고객 홈 / 탈퇴 요청 완료 → 가입·로그인 선택

### 반려동물 등록·정보 관리

여러 반려동물, 사진·체중·건강·행동 특성, 매장 기록 연결을 관리합니다.

- **내 반려동물 목록** (고객 · 목록 · 확장 설계)
  - 목적: 등록한 아이를 선택하거나 새로 등록합니다.
  - 규칙: 매장 고객 대장과의 연결은 보호자 확인 후 처리합니다.
  - 이동: 몽이 상세 → 반려동물 상세·체중 이력 / 반려동물 등록 → 반려동물 기본 정보·사진 / 매장 기록 연결 → 매장 고객 기록 연결 요청
- **반려동물 기본 정보·사진** (고객 · 등록 · 확장 설계)
  - 목적: 견종·성별·생일·몸무게·사진을 등록합니다.
  - 규칙: 필수 항목은 이름·종류입니다. 모르는 생일과 몸무게는 미입력으로 유지합니다.
  - 이동: 등록 내용 확인 → 건강·행동·관리 특성 / 작성 취소 → 내 반려동물 목록
- **건강·행동·관리 특성** (고객 · 등록 · 확장 설계)
  - 목적: 알레르기·질환·입질·싫어하는 접촉과 선호 스타일을 기록합니다.
  - 규칙: 건강 정보의 활용 범위를 안내하고 매장 공유 동의를 받습니다.
  - 이동: 반려동물 저장 → 반려동물 상세·체중 이력 / 기본 정보로 → 반려동물 기본 정보·사진
- **반려동물 상세·체중 이력** (고객 · 조회 · 확장 설계)
  - 목적: 기본 정보와 고객 입력 체중, 방문 측정 체중을 구분합니다.
  - 규칙: 고객 수정이 과거 방문 기록의 체중을 덮어쓰지 않습니다.
  - 이동: 정보 수정 → 반려동물 기본 정보·사진 / 사진 업로드 실패 보기 → 사진 형식·용량 오류 / 매장 기록 연결 → 매장 고객 기록 연결 요청 / 프로필 삭제 → 프로필 삭제 영향 확인
- **사진 형식·용량 오류** (고객 · 예외 · 확장 설계)
  - 목적: 잘못된 사진과 업로드 실패를 안내합니다.
  - 규칙: 기존 사진은 새 사진 저장 성공 전까지 유지합니다.
  - 이동: 사진 다시 선택 → 반려동물 기본 정보·사진
- **매장 고객 기록 연결 요청** (고객 · 확인 · 확장 설계)
  - 목적: 휴대폰 확인과 매장 승인으로 기존 기록을 연결합니다.
  - 규칙: 이름만 같다고 자동 연결하지 않습니다. 다른 보호자 데이터는 노출하지 않습니다.
  - 이동: 연결 요청 → 매장 연결 확인 대기 / 요청 취소 → 내 반려동물 목록
- **매장 연결 확인 대기** (고객 · 결과 · 확장 설계)
  - 목적: 사장님이 기존 고객과 반려동물 소유 관계를 확인합니다.
  - 규칙: 중복 프로필은 승인 없이 자동 병합하지 않습니다.
  - 이동: 목록으로 → 내 반려동물 목록
- **프로필 삭제 영향 확인** (고객 · 확인 · 확장 설계)
  - 목적: 진행 중 예약과 남아 있는 방문 기록을 안내합니다.
  - 규칙: 예약이 있으면 정리를 먼저 안내합니다. 거래 기록을 연쇄 삭제하지 않습니다.
  - 이동: 예약 정리 필요 → 반려동물 상세·체중 이력 / 프로필 숨김 요청 → 내 반려동물 목록

### 날짜 선택·예약금·사장님 승인

고객 신청과 사장님 검토를 한 흐름에 연결합니다. 변경 요청은 재선택·재검토를 반복합니다.

- **홈 · 예약 시작** (고객 · 진입 · 확장 설계)
  - 목적: 내 반려동물을 고르고 예약하기로 진입합니다.
  - 규칙: 연결된 매장, 로그인·프로필 상태를 확인합니다.
  - 이동: 예약하기 → 예약 캘린더 · 날짜와 시간 / 반려동물 미등록 → 예약 전 반려동물 확인
- **예약 전 반려동물 확인** (고객 · 예외 · 확장 설계)
  - 목적: 등록된 아이가 없으면 등록을 안내합니다.
  - 규칙: 프로필 등록 후 선택한 매장으로 돌아옵니다.
  - 이동: 등록 완료 후 예약으로 → 예약 캘린더 · 날짜와 시간
- **예약 캘린더 · 날짜와 시간** (고객 · 선택 · 확장 설계)
  - 목적: 달력과 시간표에서 희망 일정을 선택합니다.
  - 규칙: 여기서는 잠정 시간입니다. 서비스 선택 후 총 소요 시간으로 가능 여부를 다시 확인합니다.
  - 이동: 항목 선택 → 예약 항목 복수 선택 · 요청 / 가능한 시간 없음 → 휴무·예약 마감 안내
- **휴무·예약 마감 안내** (고객 · 예외 · 확장 설계)
  - 목적: 휴무와 마감 시간을 구분해 보여줍니다.
  - 규칙: 다른 날짜로 이동하거나 매장에 문의합니다.
  - 이동: 다른 날짜 선택 → 예약 캘린더 · 날짜와 시간
- **예약 항목 복수 선택 · 요청** (고객 · 선택 · 확장 설계)
  - 목적: 목욕·위생미용 등 항목을 복수 선택합니다.
  - 규칙: 기본 서비스 중복 조합은 매장 설정으로 제한합니다. 합산 시간에 빈자리가 없으면 재선택합니다.
  - 이동: 예상 요금·정책 확인 → 예약 내용 · 예약금 정책 확인 / 총 소요 시간 초과 → 휴무·예약 마감 안내 / 날짜 다시 선택 → 예약 캘린더 · 날짜와 시간
- **예약 내용 · 예약금 정책 확인** (고객 · 확인 · 확장 설계)
  - 목적: 선택 항목·시간·요청과 취소·환불 규정을 확인합니다.
  - 규칙: 예약금은 최종 미용 금액에 충당합니다. 여기의 1만원은 검토용 예시이며 매장 정책으로 결정합니다.
  - 이동: 예약금 결제 → 예약금 결제 진행 / 항목 수정 → 예약 항목 복수 선택 · 요청
- **예약금 결제 진행** (고객 · 결제 · 확장 설계)
  - 목적: 결제창에서 예약금을 결제합니다.
  - 규칙: 결제 요청에 중복 방지 키를 사용하고 서버 결제 확인 후에만 검토 대기로 전환합니다.
  - 이동: 결제 성공 → 사장님 확인 대기 / 결제 실패 → 예약금 결제 실패 / 결제창 닫음 → 예약 내용 · 예약금 정책 확인 / 결과 확인 지연 → 결제 결과 확인 중
- **예약금 결제 실패** (고객 · 예외 · 확장 설계)
  - 목적: 실패 사유를 안내하고 재시도합니다.
  - 규칙: 실패한 결제로 예약을 확정하지 않습니다. 임시 시간 점유는 유효시간 후 해제합니다.
  - 이동: 결제 재시도 → 예약금 결제 진행 / 신청 내용으로 → 예약 내용 · 예약금 정책 확인
- **결제 결과 확인 중** (고객 · 예외 · 확장 설계)
  - 목적: 승인 응답이 늦을 때 결제 내역을 조회합니다.
  - 규칙: 다시 결제하게 하지 않습니다. 결제 성공·실패를 대사한 뒤 상태를 결정합니다.
  - 이동: 결제 확인됨 → 사장님 확인 대기 / 승인 없음 확인 → 예약금 결제 실패
- **사장님 확인 대기** (고객 · 상태 · 확장 설계)
  - 목적: 예약금 결제 후 신청을 보관합니다.
  - 규칙: 고객에게 확정 전임을 표시합니다. 응답 기한과 자동 취소 여부는 매장 정책 결정이 필요합니다.
  - 이동: 사장님 검토 화면 보기 → 사장님 · 신청 검토 / 고객 신청 취소 → 고객 · 취소 사유와 환불 확인
- **사장님 · 신청 검토** (사장님 · 검토 · 확장 설계)
  - 목적: 아이 정보·요청·항목·일정·예약금을 확인합니다.
  - 규칙: 일정 중복과 서비스 수행 가능 여부를 확인한 뒤 결정합니다.
  - 이동: 예약 확정 → 예약 확정 · 고객 확인 / 일정 변경 요청 → 사장님 · 변경 요청 사유 / 예약 취소·거절 → 사장님 · 취소 사유 확인
- **사장님 · 변경 요청 사유** (사장님 · 수정 · 확장 설계)
  - 목적: 변경 이유와 가능한 대체 일정을 안내합니다.
  - 규칙: 고객의 동의 없이 날짜를 확정하지 않습니다. 예약금은 유지하고 재승인 단계로 보냅니다.
  - 이동: 변경 요청 보내기 → 고객 · 일정 변경 요청 수신 / 검토로 돌아가기 → 사장님 · 신청 검토
- **고객 · 일정 변경 요청 수신** (고객 · 상태 · 확장 설계)
  - 목적: 사장님 사유와 제안 일정을 확인합니다.
  - 규칙: 제안을 수락하거나 다른 날짜를 골라도 다시 사장님 검토를 거칩니다.
  - 이동: 다른 날짜 선택 → 고객 · 날짜·시간 재선택 / 제안 일정으로 신청 → 변경 신청 · 재검토 대기 / 변경 대신 취소 → 고객 · 취소 사유와 환불 확인
- **고객 · 날짜·시간 재선택** (고객 · 선택 · 확장 설계)
  - 목적: 다른 가능한 날짜·시간을 선택합니다.
  - 규칙: 동일 요금이면 예약금을 또 받지 않습니다. 요금 차이는 재확인하며 추가 결제·부분환불 정책은 별도 확정합니다.
  - 이동: 변경 신청 제출 → 변경 신청 · 재검토 대기 / 선택 취소 → 고객 · 일정 변경 요청 수신
- **변경 신청 · 재검토 대기** (고객 · 상태 · 확장 설계)
  - 목적: 선택한 새 일정을 다시 제출합니다.
  - 규칙: 최종 확정 전까지 변경 요청과 재선택이 반복될 수 있습니다. 기존·제안 일정의 점유 정책을 명시해야 합니다.
  - 이동: 사장님 재검토 → 사장님 · 신청 검토 / 고객 취소 → 고객 · 취소 사유와 환불 확인
- **사장님 · 취소 사유 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 거절·취소 사유를 필수로 입력합니다.
  - 규칙: 매장 사유 취소는 예약금 전액 환불을 제안합니다. 결제 취소 성공 전까지 환불 대기로 표시합니다.
  - 이동: 취소·환불 요청 → 예약 취소 · 환불 처리 대기 / 계속 검토 → 사장님 · 신청 검토
- **고객 · 취소 사유와 환불 확인** (고객 · 확인 · 확장 설계)
  - 목적: 취소 사유·환불 예정액·규정을 확인합니다.
  - 규칙: 기한과 귀책 사유에 따른 금액을 사전에 안내합니다. 구체적 위약금은 아직 결정하지 않습니다.
  - 이동: 취소 요청 확정 → 예약 취소 · 환불 처리 대기 / 예약 유지 → 사장님 확인 대기
- **예약 취소 · 환불 처리 대기** (고객 · 상태 · 확장 설계)
  - 목적: 예약 취소와 결제 취소 상태를 구분합니다.
  - 규칙: 환불 실패 시 재처리·문의 경로를 제공합니다. 승인 여부가 불명확하면 중복 환불을 막습니다.
  - 이동: 환불 완료 → 취소·환불 완료 / 환불 실패 → 환불 실패 · 재처리
- **환불 실패 · 재처리** (고객 · 예외 · 확장 설계)
  - 목적: 고객에게 처리 중임을 알리고 사장님이 확인합니다.
  - 규칙: 예약을 다시 확정하지 않습니다. PG 대사 후 미환불 건만 재처리합니다.
  - 이동: 환불 재확인 → 예약 취소 · 환불 처리 대기
- **취소·환불 완료** (고객 · 결과 · 확장 설계)
  - 목적: 취소 이유와 반환 금액을 영수 내역에 남깁니다.
  - 규칙: 예약·결제·환불 이력을 삭제하지 않습니다.
  - 이동: 새 예약하기 → 예약 캘린더 · 날짜와 시간
- **예약 확정 · 고객 확인** (고객 · 결과 · 확장 설계)
  - 목적: 확정 날짜·시간·서비스·예약금·방문 안내를 보여줍니다.
  - 규칙: 확정만으로 미용 완료나 매출 전액으로 처리하지 않습니다. 고객 알림 실패는 별도로 재시도합니다.
  - 이동: 홈으로 → 홈 · 예약 시작 / 확정 후 변경·취소 안내 → 확정 후 변경·취소 요청
- **확정 후 변경·취소 요청** (고객 · 확인 · 확장 설계)
  - 목적: 방문이 임박했는지와 정책을 확인합니다.
  - 규칙: 변경 승인 전 원예약을 조용히 삭제하지 않습니다. 매장 승인과 환불 규정을 함께 적용합니다.
  - 이동: 일정 변경 요청 → 고객 · 날짜·시간 재선택 / 취소·환불 확인 → 고객 · 취소 사유와 환불 확인 / 예약 유지 → 예약 확정 · 고객 확인

### 예약 내역·미용수첩·문의

다가오는 예약부터 방문 이력, 공개된 전후 기록과 문의까지.

- **내 예약 목록** (고객 · 목록 · 확장 설계)
  - 목적: 대기·변경 요청·확정·취소 예약을 구분합니다.
  - 규칙: 고객 본인과 연결된 반려동물 예약만 조회합니다.
  - 이동: 예약 상세 → 내 예약 상세·금액 내역 / 미용수첩 → 반려동물별 미용수첩 목록 / 매장 공지·문의 → 공지·매장 문의·정보 정정
- **내 예약 상세·금액 내역** (고객 · 조회 · 확장 설계)
  - 목적: 예약금·추가금·잔액·취소·환불 상태를 보여줍니다.
  - 규칙: 장부 내부 메모와 다른 고객 정보는 노출하지 않습니다.
  - 이동: 변경·취소 문의 → 공지·매장 문의·정보 정정 / 예약 목록 → 내 예약 목록
- **반려동물별 미용수첩 목록** (고객 · 목록 · 확장 설계)
  - 목적: 방문별 체중과 스타일 변화를 봅니다.
  - 규칙: 공개된 방문 기록만 보여줍니다.
  - 이동: 미용 기록 상세 → 전후 사진·소견·홈케어 / 예약 목록 → 내 예약 목록
- **전후 사진·소견·홈케어** (고객 · 조회 · 확장 설계)
  - 목적: 미용 전후 사진, 피부·털 상태와 다음 관리 조언을 확인합니다.
  - 규칙: 사진은 해당 방문에 연결합니다. 고객 비공개 메모는 제외합니다.
  - 이동: 기록 정정·문의 → 공지·매장 문의·정보 정정 / 수첩 목록 → 반려동물별 미용수첩 목록
- **공지·매장 문의·정보 정정** (고객 · 문의 · 확장 설계)
  - 목적: 공지 목록과 문의할 예약·방문 기록을 선택합니다.
  - 규칙: 실시간 채팅을 제공하는 것으로 표시하지 않습니다. 문의 채널과 답변 시간은 운영 정책으로 결정합니다.
  - 이동: 문의 접수 → 문의 접수·답변 대기 / 목록으로 → 내 예약 목록
- **문의 접수·답변 대기** (고객 · 결과 · 확장 설계)
  - 목적: 접수 번호와 답변 확인 방법을 안내합니다.
  - 규칙: 예약 상태는 답변만으로 바뀌지 않습니다.
  - 이동: 내 예약으로 → 내 예약 목록

### 고객의 예약과 미용수첩

요금을 확인하고 예약을 신청한 뒤, 우리 아이의 공개된 관리 기록을 봅니다.

- **고객 홈 · 미용수첩** (고객 · 첫 화면 · 기존 구현 기반)
  - 목적: 연결된 반려견, 공개된 미용 기록과 매장 공지를 확인합니다.
  - 규칙: 사장님 메뉴와 주소·권한이 분리됩니다. 내 반려견의 공개 기록만 보여줍니다.
  - 이동: 몽이 미용수첩 → 몽이의 미용수첩 / 요금표 보기 → 고객 요금표 / 예약 신청 → 예약 신청
- **고객 요금표** (고객 · 조회 · 기존 구현 기반)
  - 목적: 견종·체중·서비스별 요금을 세로로 이어 봅니다.
  - 규칙: 사장님이 저장한 같은 원본을 읽습니다. 분류 탭과 편집 버튼은 없습니다.
  - 이동: 예약 신청하기 → 예약 신청 / 고객 홈 → 고객 홈 · 미용수첩
- **예약 신청** (고객 · 등록 · 기존 구현 기반)
  - 목적: 아이 정보, 서비스와 방문 시간을 입력합니다.
  - 규칙: 예약 가능한 요금 항목을 연결한 매장을 가정한 예시입니다. 설정이 없으면 실제 앱은 준비 중으로 표시합니다.
  - 이동: 신청 내용 확인 → 예약 신청 확인 / 작성 취소 → 고객 홈 · 미용수첩
- **예약 신청 확인** (고객 · 확인 · 기존 구현 기반)
  - 목적: 신청 시간과 예상 금액, 연락처를 다시 확인합니다.
  - 규칙: 신청은 즉시 확정이나 결제가 아닙니다. 사장님이 수락한 뒤 예약에 반영합니다.
  - 이동: 예약 신청 보내기 → 신청 접수 / 내용 수정 → 예약 신청
- **신청 접수** (고객 · 결과 · 기존 구현 기반)
  - 목적: 접수 결과와 확정 전 상태를 안내합니다.
  - 규칙: 현재는 신청 접수와 사장님 승인 처리가 구현되어 있습니다. 자동 메시지 발송은 별도 연동이 필요합니다.
  - 이동: 고객 홈 → 고객 홈 · 미용수첩 / 확정 알림 구상 보기 → 예약 확정 알림
- **몽이의 미용수첩** (고객 · 조회 · 기존 구현 기반)
  - 목적: 방문별 체중, 미용 전후 사진과 관리 조언을 봅니다.
  - 규칙: 사장님이 공개한 기록만 표시합니다. 내부 메모와 장부는 노출하지 않습니다.
  - 이동: 다음 미용 예약 → 예약 신청 / 고객 홈 → 고객 홈 · 미용수첩
- **예약 확정 알림** (고객 · 후속 설계 · 확장 설계)
  - 목적: 예약이 확정되면 보호자가 바로 알 수 있게 합니다.
  - 규칙: 알림 채널 선택·동의·발송 및 재시도는 아직 구현 범위가 아닙니다. 이 화면은 검토용 제안입니다.
  - 이동: 접수 화면으로 → 신청 접수

## 사장님 시나리오

### 매장 개설·영업·예약 정책

매장 기본 정보, 휴무·시간·서비스·예약금 규정을 준비하고 고객 화면을 점검합니다.

- **내 매장·운영 준비 현황** (사장님 · 목록 · 확장 설계)
  - 목적: 현재 매장과 설정 누락을 확인합니다.
  - 규칙: 처음은 단일 매장이지만 데이터·권한에는 매장 식별자가 필요합니다.
  - 이동: 매장 기본 정보 → 매장 정보·담당자 설정 / 영업 일정 → 영업시간·휴무·차단 일정 / 예약 정책 → 예약금·취소·환불 규정 / 고객 화면 점검 → 고객 화면·예약 가능 여부 점검
- **매장 정보·담당자 설정** (사장님 · 수정 · 확장 설계)
  - 목적: 매장명·위치·연락처·로고와 담당자를 관리합니다.
  - 규칙: 고객 공지는 별도 게시판에서 관리합니다.
  - 이동: 저장 → 내 매장·운영 준비 현황 / 취소 → 내 매장·운영 준비 현황
- **영업시간·휴무·차단 일정** (사장님 · 목록 · 확장 설계)
  - 목적: 영업시간과 휴무일, 쉬는 시간을 확인합니다.
  - 규칙: 차단 시간에 이미 예약이 있으면 영향 예약을 먼저 보여줍니다.
  - 이동: 휴무·차단 등록 → 휴무 등록·영향 예약 확인 / 서비스·시간 연결 → 요금·소요시간·조합 설정 / 매장으로 → 내 매장·운영 준비 현황
- **휴무 등록·영향 예약 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 차단할 기간과 영향을 받는 예약을 확인합니다.
  - 규칙: 차단만으로 기존 예약을 취소하지 않습니다. 고객 변경·취소 절차를 각각 진행합니다.
  - 이동: 예약 영향 확인 후 저장 → 영업시간·휴무·차단 일정 / 취소 → 영업시간·휴무·차단 일정
- **요금·소요시간·조합 설정** (사장님 · 수정 · 확장 설계)
  - 목적: 공개 요금표와 예약 가능한 서비스를 연결합니다.
  - 규칙: 기본 서비스 중복 조합, 추가 항목 시간, 체중 범위를 명시합니다.
  - 이동: 연결 설정 저장 → 내 매장·운영 준비 현황
- **예약금·취소·환불 규정** (사장님 · 수정 · 확장 설계)
  - 목적: 예약금 방식, 무료 취소 기한, 매장 취소 환불 규정을 정합니다.
  - 규칙: 운영 전 확정할 정책입니다. 저장한 정책 버전을 예약 신청과 함께 보존해야 합니다.
  - 이동: 정책 미리보기 → 고객 화면·예약 가능 여부 점검 / 취소 → 내 매장·운영 준비 현황
- **고객 화면·예약 가능 여부 점검** (사장님 · 조회 · 확장 설계)
  - 목적: 요금·영업시간·정책·공지의 공개 내용을 확인합니다.
  - 규칙: 필수 설정이 누락되면 온라인 예약을 준비 중으로 표시합니다.
  - 이동: 운영 준비 목록 → 내 매장·운영 준비 현황 / 필수 설정 누락 → 온라인 예약 준비 중
- **온라인 예약 준비 중** (사장님 · 예외 · 확장 설계)
  - 목적: 누락한 정책·요금·시간 설정으로 안내합니다.
  - 규칙: 고객에게 예약 가능하다고 잘못 표시하지 않습니다.
  - 이동: 설정 보완 → 예약금·취소·환불 규정

### 예약 신청 검토·변경·거절

요청 목록과 변경 이력을 보고 예약금 상태를 확인한 뒤 결정합니다.

- **신청·변경 요청 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 새 신청·재검토·기한 임박 건을 구분합니다.
  - 규칙: 고객이 선택한 항목과 총 소요 시간, 예약금 납부 상태를 표시합니다.
  - 이동: 신청 상세 → 신청 상세·검토 이력 / 미응답 기한 도래 → 미응답·임시 점유 만료
- **신청 상세·검토 이력** (사장님 · 조회 · 확장 설계)
  - 목적: 반려동물 주의사항과 변경 전후 일정을 확인합니다.
  - 규칙: 결제 확인과 시간 중복을 서버에서 다시 검사합니다.
  - 이동: 예약 확정 → 확정 전 일정 재확인 / 일정 변경 요청 → 변경 사유·가능 시간 제안 / 사유 입력 후 거절 → 거절·취소 사유와 환불 / 결제 확인 필요 → 예약금 결제·환불 대사
- **확정 전 일정 재확인** (사장님 · 확인 · 확장 설계)
  - 목적: 최종 일정과 고객 요청을 확인합니다.
  - 규칙: 같은 시간의 다른 확정과 충돌하면 중단합니다.
  - 이동: 확정 처리 → 예약 확정·알림 발송 상태 / 시간 충돌 → 동일 시간 확정 충돌
- **동일 시간 확정 충돌** (사장님 · 예외 · 확장 설계)
  - 목적: 새로 잡힌 다른 예약을 확인합니다.
  - 규칙: 고객 신청을 잃지 않고 대체 시간을 요청합니다.
  - 이동: 변경 요청 → 변경 사유·가능 시간 제안 / 신청 상세 → 신청 상세·검토 이력
- **변경 사유·가능 시간 제안** (사장님 · 수정 · 확장 설계)
  - 목적: 고객에게 변경 이유와 대체 시간을 보냅니다.
  - 규칙: 고객 재선택은 확정이 아니라 재검토 요청입니다.
  - 이동: 변경 요청 전송 → 고객 답변 대기 / 취소 → 신청 상세·검토 이력
- **고객 답변 대기** (사장님 · 상태 · 확장 설계)
  - 목적: 변경 제안을 보낸 상태와 응답 기한을 봅니다.
  - 규칙: 기한 초과 처리와 시간 점유 해제 정책은 운영 전에 결정해야 합니다.
  - 이동: 고객이 새 일정 제출 → 신청 상세·검토 이력 / 고객이 취소 요청 → 거절·취소 사유와 환불 / 목록 → 신청·변경 요청 목록
- **거절·취소 사유와 환불** (사장님 · 확인 · 확장 설계)
  - 목적: 고객에게 보일 사유와 예약금 환불을 확인합니다.
  - 규칙: 매장 사유 취소 전액 환불을 기본 제안으로 검토합니다. 환불 성공 여부를 별도 기록합니다.
  - 이동: 취소·환불 처리 → 환불 처리 결과 / 검토 유지 → 신청 상세·검토 이력
- **환불 처리 결과** (사장님 · 상태 · 확장 설계)
  - 목적: 환불 완료·실패·확인 중을 구분합니다.
  - 규칙: 실패 건은 환불 관리에서 재확인합니다.
  - 이동: 처리 완료 후 목록 → 신청·변경 요청 목록 / 환불 재확인 → 예약금 결제·환불 대사
- **예약금 결제·환불 대사** (사장님 · 예외 · 확장 설계)
  - 목적: PG 상태와 내부 거래 기록을 확인합니다.
  - 규칙: 중복 청구·환불을 방지하고 원거래와 취소거래를 연결합니다.
  - 이동: 확인 후 상세 → 신청 상세·검토 이력
- **미응답·임시 점유 만료** (사장님 · 예외 · 확장 설계)
  - 목적: 처리 기한이 지난 신청을 확인합니다.
  - 규칙: 시간만 자동 해제할지 예약금도 취소할지 정책을 확정해야 합니다.
  - 이동: 신청 확인 → 신청 상세·검토 이력 / 취소·환불 검토 → 거절·취소 사유와 환불
- **예약 확정·알림 발송 상태** (사장님 · 결과 · 확장 설계)
  - 목적: 캘린더 반영과 고객 통지 결과를 확인합니다.
  - 규칙: 알림 실패가 확정 상태를 되돌리지는 않습니다. 발송만 재시도합니다.
  - 이동: 신청 목록 → 신청·변경 요청 목록

### 고객·반려동물·기록 연결

고객 목록, 여러 반려동물, 고객 계정 연결 승인과 정보 정정을 관리합니다.

- **고객 검색 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 보호자명·반려동물명·연락처로 검색합니다.
  - 규칙: 전화번호 뒤 4자리는 검색 결과 식별용이며 개인정보 조회 권한은 별도입니다.
  - 이동: 고객 상세 → 고객·아이 상세와 방문 이력 / 새 고객·반려동물 → 고객·반려동물 등록 / 계정 연결 요청 → 고객 계정 연결 승인
- **고객·반려동물 등록** (사장님 · 등록 · 확장 설계)
  - 목적: 보호자와 아이를 연결해 등록합니다.
  - 규칙: 기존 연락처가 있으면 중복 후보를 먼저 보여줍니다.
  - 이동: 등록 → 고객·아이 상세와 방문 이력 / 중복 후보 확인 → 중복 후보·별도 등록 검토 / 취소 → 고객 검색 목록
- **고객·아이 상세와 방문 이력** (사장님 · 조회 · 확장 설계)
  - 목적: 연락처, 각 아이의 주의사항과 방문·결제·사진을 봅니다.
  - 규칙: 보호자 공통 정보와 아이별 기록을 구분합니다.
  - 이동: 정보 수정 → 보호자·반려동물 정보 수정 / 고객 연결 승인 → 고객 계정 연결 승인 / 고객 보관 처리 → 고객 보관·연결 해제 확인 / 목록 → 고객 검색 목록
- **보호자·반려동물 정보 수정** (사장님 · 수정 · 확장 설계)
  - 목적: 연락처와 최신 주의사항을 정정합니다.
  - 규칙: 과거 예약에 저장된 금액·체중·견종 스냅샷은 덮어쓰지 않습니다.
  - 이동: 수정 저장 → 고객·아이 상세와 방문 이력 / 취소 → 고객·아이 상세와 방문 이력
- **중복 후보·별도 등록 검토** (사장님 · 확인 · 확장 설계)
  - 목적: 동명이인과 중복 프로필 후보를 비교합니다.
  - 규칙: 자동 병합하지 않습니다. 병합 기능은 이력·권한 설계 후 별도 도입합니다.
  - 이동: 기존 고객 사용 → 고객·아이 상세와 방문 이력 / 별도 고객으로 등록 → 고객·반려동물 등록
- **고객 계정 연결 승인** (사장님 · 확인 · 확장 설계)
  - 목적: 고객 본인 확인과 반려동물 소유 관계를 확인합니다.
  - 규칙: 승인 뒤 해당 아이의 공개 기록만 고객이 조회합니다.
  - 이동: 연결 승인 → 고객·아이 상세와 방문 이력 / 연결 거절 → 고객 검색 목록
- **고객 보관·연결 해제 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 사용 중지와 고객 계정 연결 해제를 구분합니다.
  - 규칙: 예약·결제 기록을 함께 삭제하지 않습니다.
  - 이동: 보관 처리 → 고객 검색 목록 / 유지 → 고객·아이 상세와 방문 이력

### 예약금·최종 정산·환불·장부

예약금과 최종 결제를 중복 집계하지 않고 환불·운영비와 구분해 관리합니다.

- **결제·미수·예약금 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 받은 예약금, 방문 잔액, 환불 대기 건을 봅니다.
  - 규칙: 예약 예상액·실제 현금 유입·미용 완료 기준 수익은 구분합니다.
  - 이동: 방문 최종 정산 → 미용 완료·추가금·잔액 확인 / 환불 관리 → 환불·실패·미처리 목록 / 운영비 목록 → 운영비·샴푸 구매 목록 / 월별 장부·내보내기 → 월별 장부·내보내기
- **미용 완료·추가금·잔액 확인** (사장님 · 처리 · 확장 설계)
  - 목적: 최종 서비스·추가 요금·할인·기납부 예약금을 확인합니다.
  - 규칙: 예: 총 5만원−예약금 1만원=잔액 4만원. 예약금을 총액에 다시 더하지 않습니다.
  - 이동: 잔액 결제 기록 → 최종 정산 완료 / 추가금 보호자 확인 필요 → 추가 작업·요금 동의 확인
- **추가 작업·요금 동의 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 엉킴·입질 등 추가 작업과 비용을 보호자에게 안내합니다.
  - 규칙: 원가 기록과 고객 추가 청구를 구분합니다. 동의 시각·내용 보존 정책을 검토합니다.
  - 이동: 확인 후 정산 → 미용 완료·추가금·잔액 확인 / 추가 작업 보류 → 결제·미수·예약금 목록
- **최종 정산 완료** (사장님 · 결과 · 확장 설계)
  - 목적: 예약금과 잔액을 연결해 총 수납액을 확인합니다.
  - 규칙: 중복 완료를 막습니다. 결제 후 금액 수정은 별도 정정·취소 기록으로 처리합니다.
  - 이동: 결제 목록 → 결제·미수·예약금 목록 / 결제 정정 요청 → 결제 정정·취소 사유 확인
- **결제 정정·취소 사유 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 원결제와 정정 사유를 확인합니다.
  - 규칙: 기존 결제를 조용히 덮어쓰지 않습니다. 승인·환불과 장부 정정 이력을 연결해야 합니다.
  - 이동: 정정 검토 접수 → 환불·실패·미처리 목록 / 유지 → 최종 정산 완료
- **환불·실패·미처리 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 원거래별 환불 대상과 처리 상태를 확인합니다.
  - 규칙: 전액·부분 환불과 예약 취소를 구분합니다.
  - 이동: 환불 상세·재처리 → 환불 상세·원거래 대사 / 결제 목록 → 결제·미수·예약금 목록
- **환불 상세·원거래 대사** (사장님 · 처리 · 확장 설계)
  - 목적: 원금·환불 누계·잔여 환불 가능액을 확인합니다.
  - 규칙: 승인 결과가 불명확하면 조회 후 재시도합니다. 원금보다 많이 환불하지 않습니다.
  - 이동: 환불 확인 완료 → 환불·실패·미처리 목록 / 실패·재확인 대기 → 환불·실패·미처리 목록
- **운영비·샴푸 구매 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 임대료·용품·샴푸 구매 등 비용을 관리합니다.
  - 규칙: 샴푸 구매를 비용 기록했다면 방문 사용 원가를 다시 비용 차감하지 않습니다.
  - 이동: 운영비 등록 → 운영비 등록·영수 메모 / 장부 → 월별 장부·내보내기
- **운영비 등록·영수 메모** (사장님 · 등록 · 확장 설계)
  - 목적: 날짜·분류·금액·메모를 입력합니다.
  - 규칙: 등록·수정·삭제와 결제 장부를 구분하고 관련 이력을 보존해야 합니다.
  - 이동: 비용 저장 → 운영비·샴푸 구매 목록 / 취소 → 운영비·샴푸 구매 목록
- **월별 장부·내보내기** (사장님 · 조회 · 확장 설계)
  - 목적: 기간별 수납·환불·운영비와 미수를 확인합니다.
  - 규칙: 날짜 기준과 합계를 명시합니다. CSV는 백업 전체가 아닙니다.
  - 이동: CSV 내보내기 예시 → 내보내기 결과 / 목록 → 결제·미수·예약금 목록
- **내보내기 결과** (사장님 · 결과 · 확장 설계)
  - 목적: 기간·기준·포함 항목을 확인합니다.
  - 규칙: 이 프로토타입은 파일을 실제 생성하지 않습니다. 개인정보 포함 범위를 확인해야 합니다.
  - 이동: 장부로 → 월별 장부·내보내기

### 로그인·권한·백업·복원

운영자 접근, 세션 만료, 데이터 백업과 복원 실패를 다룹니다.

- **사장님 로그인** (사장님 · 인증 · 확장 설계)
  - 목적: 매장 운영 권한으로 로그인합니다.
  - 규칙: 고객 로그인과 별도 권한입니다. URL만 바꿔 운영 화면에 접근할 수 없어야 합니다.
  - 이동: 로그인 성공 → 매장 운영·보호 설정 / 권한 없음 → 접근 권한 없음
- **매장 운영·보호 설정** (사장님 · 목록 · 확장 설계)
  - 목적: 현재 매장·로그인과 백업 상태를 확인합니다.
  - 규칙: 다른 매장 데이터 접근은 서버에서 차단합니다.
  - 이동: 백업 현황 → 백업 현황·복원 지점 목록 / 세션 만료 상황 → 세션 만료·초안 보존 / 직원 권한 검토 → 사장님·직원·고객 권한
- **세션 만료·초안 보존** (사장님 · 예외 · 확장 설계)
  - 목적: 재로그인을 안내하고 가능한 초안을 유지합니다.
  - 규칙: 재로그인 후 저장 전에 서버 최신 버전을 확인합니다.
  - 이동: 다시 로그인 → 사장님 로그인
- **접근 권한 없음** (사장님 · 예외 · 확장 설계)
  - 목적: 권한 없는 매장·고객 데이터에 접근을 차단합니다.
  - 규칙: 정보 존재 여부와 본문을 노출하지 않습니다.
  - 이동: 로그인으로 → 사장님 로그인
- **사장님·직원·고객 권한** (사장님 · 검토 · 확장 설계)
  - 목적: 역할별 조회·수정·환불·내보내기 권한을 정의합니다.
  - 규칙: 현재 단일 사장님 운영입니다. 직원 초대·권한 분리는 확장 설계입니다.
  - 이동: 운영 설정 → 매장 운영·보호 설정
- **백업 현황·복원 지점 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 자동 백업 시각과 검증 결과를 확인합니다.
  - 규칙: 실서버 DB·사진 파일을 함께 보존해야 합니다. Pages는 기기 동기화·서버 백업이 아닙니다.
  - 이동: 백업 만들기 → 백업 생성·검증 / 복원 지점 검토 → 복원 영향·복원 전 백업
- **백업 생성·검증** (사장님 · 처리 · 확장 설계)
  - 목적: 일관된 DB와 사진을 보관하고 복원 가능 여부를 검사합니다.
  - 규칙: 백업 실패 알림과 재시도 정책이 필요합니다.
  - 이동: 성공 → 백업 현황·복원 지점 목록 / 실패·재시도 → 백업 실패·재확인
- **백업 실패·재확인** (사장님 · 예외 · 확장 설계)
  - 목적: 실패 원인과 마지막 정상 지점을 안내합니다.
  - 규칙: 실패한 파일을 정상 백업으로 표시하지 않습니다.
  - 이동: 재시도 → 백업 생성·검증 / 목록 → 백업 현황·복원 지점 목록
- **복원 영향·복원 전 백업** (사장님 · 확인 · 확장 설계)
  - 목적: 복원 지점 이후 기록에 미칠 영향을 명시합니다.
  - 규칙: 운영 데이터 덮어쓰기 위험이 있으므로 점검 모드·복원 전 백업·별도 승인 절차가 필요합니다.
  - 이동: 검토용 복원 실행 → 복원 검증·운영 재개 점검 / 취소 → 백업 현황·복원 지점 목록
- **복원 검증·운영 재개 점검** (사장님 · 결과 · 확장 설계)
  - 목적: 예약·결제·사진과 권한을 검증한 뒤 재개합니다.
  - 규칙: 실패하면 복원 전 백업으로 돌아갈 수 있어야 합니다.
  - 이동: 검증 완료 후 목록 → 백업 현황·복원 지점 목록

### 방문 접수·미용 중·귀가·노쇼

도착부터 안전 확인, 예상치 못한 상황, 보호자 인계와 미방문 처리를 다룹니다.

- **오늘 방문·진행 상태** (사장님 · 목록 · 확장 설계)
  - 목적: 확정·도착·미용 중·인계 대기·미방문을 구분합니다.
  - 규칙: 캘린더 예약 상태와 결제 상태를 독립적으로 표시합니다.
  - 이동: 몽이 도착 접수 → 도착·체중·피부·요청 재확인 / 지각·미방문 → 지각·노쇼 확인
- **도착·체중·피부·요청 재확인** (사장님 · 확인 · 확장 설계)
  - 목적: 당일 컨디션과 변경 요청을 확인합니다.
  - 규칙: 위험 징후가 있으면 미용을 바로 시작하지 않습니다.
  - 이동: 미용 시작 → 미용 진행·전후 기록 / 안전상 진행 보류 → 진행 중단·보호자 연락 기록
- **미용 진행·전후 기록** (사장님 · 수정 · 확장 설계)
  - 목적: 전후 사진·작업 내역·사용 샴푸와 소견을 기록합니다.
  - 규칙: 내부 작업 메모와 고객에게 공개할 소견을 구분합니다.
  - 이동: 미용 완료·인계 준비 → 보호자 인계·소견 공개·정산 확인 / 중도 중단·추가 작업 상담 → 진행 중단·보호자 연락 기록
- **진행 중단·보호자 연락 기록** (사장님 · 확인 · 확장 설계)
  - 목적: 안전 문제·추가 작업 필요와 보호자 안내를 기록합니다.
  - 규칙: 임의 추가 청구나 의료 진단을 하지 않습니다. 필요 시 미용 중단과 병원 상담을 안내합니다.
  - 이동: 보호자 확인 후 재개 → 미용 진행·전후 기록 / 중단 후 인계 → 보호자 인계·소견 공개·정산 확인
- **보호자 인계·소견 공개·정산 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 아이와 주의사항을 인계하고 결제·공개 기록을 확인합니다.
  - 규칙: 인계 완료, 수납 완료, 고객 기록 공개를 각각 확인합니다.
  - 이동: 방문 마감 → 오늘 방문·진행 상태 / 공개 내용 정정 → 미용 진행·전후 기록
- **지각·노쇼 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 보호자 연락 여부와 실제 미방문을 확인합니다.
  - 규칙: 노쇼를 예약 자동 삭제로 처리하지 않습니다. 예약금 처리·다음 예약 제한은 사전 고지 정책이 필요합니다.
  - 이동: 연락 후 일정 조정 → 오늘 방문·진행 상태 / 미방문 기록 → 오늘 방문·진행 상태

### 외부 예약 채널·동기화

네이버 등 외부 예약 연동 가능 여부 확인부터 중복·충돌·실패 처리를 설계합니다.

- **예약 채널·연결 상태** (사장님 · 목록 · 확장 설계)
  - 목적: 직접 예약과 외부 채널의 연결 상태를 확인합니다.
  - 규칙: 네이버 연동은 공식 제공 범위·사업자 권한·계약 가능 여부 확인이 선행되어야 합니다.
  - 이동: 연동 조건 확인 → 공식 연동 범위·권한 확인 / 동기화 오류 → 연결 실패·권한 만료·미지원
- **공식 연동 범위·권한 확인** (사장님 · 검토 · 확장 설계)
  - 목적: 예약 조회·변경·취소·알림의 지원 범위를 확인합니다.
  - 규칙: 공식 연동 가능하다고 확정하지 않습니다. 미지원이면 수동 입력·링크 안내 범위로 제한합니다.
  - 이동: 외부 예약 수신 가정 → 외부 예약 수신·중복 확인 / 연동 미지원 → 연결 실패·권한 만료·미지원
- **외부 예약 수신·중복 확인** (사장님 · 처리 · 확장 설계)
  - 목적: 채널 예약 ID로 동일 요청을 식별합니다.
  - 규칙: 재수신은 새 예약을 만들지 않습니다. 채널명·외부 ID·변경 이력을 보존합니다.
  - 이동: 일정 일치·반영 → 예약 채널·연결 상태 / 자체 예약과 시간 충돌 → 채널 간 예약 충돌
- **채널 간 예약 충돌** (사장님 · 예외 · 확장 설계)
  - 목적: 기존 예약과 새 수신 예약을 비교합니다.
  - 규칙: 어느 쪽도 조용히 삭제하거나 무조건 확정하지 않습니다. 사장님이 고객과 조정합니다.
  - 이동: 수동 조정·확인 기록 → 예약 채널·연결 상태 / 재확인 → 외부 예약 수신·중복 확인
- **연결 실패·권한 만료·미지원** (사장님 · 예외 · 확장 설계)
  - 목적: 마지막 정상 동기화와 현재 제한을 표시합니다.
  - 규칙: 연동 실패를 예약 없음으로 표시하지 않습니다. 재시도·수동 확인 경로를 제공합니다.
  - 이동: 권한·연동 범위 재확인 → 공식 연동 범위·권한 확인 / 목록 → 예약 채널·연결 상태

### 샴푸·사용 원가 관리

제품 목록, 사진·구매가·용량·희석비와 방문별 사용 기록을 관리합니다.

- **샴푸 제품 목록** (사장님 · 목록 · 확장 설계)
  - 목적: 제품 사진과 사용 여부를 확인합니다.
  - 규칙: 사진이 없으면 대체 이미지를 제공하고 검색으로 찾습니다.
  - 이동: 제품 상세 → 제품 상세·원가 기준 / 제품 등록 → 샴푸 사진·구매 정보 입력
- **제품 상세·원가 기준** (사장님 · 조회 · 확장 설계)
  - 목적: 실제 구매가와 용량, 라벨 희석비를 확인합니다.
  - 규칙: 희석비는 제조사 기준을 직접 기록합니다. 샴푸 사용 원가와 고객 추가금은 별도입니다.
  - 이동: 제품 수정 → 샴푸 사진·구매 정보 입력 / 방문 사용 기록 → 방문별 사용량·추가 청구 / 사용 중지 → 제품 사용 중지 확인
- **샴푸 사진·구매 정보 입력** (사장님 · 수정 · 확장 설계)
  - 목적: 제품명·사진·구매금액·용량·희석비를 입력합니다.
  - 규칙: 구매 정보 변경이 과거 방문의 저장 원가를 다시 계산하지 않습니다.
  - 이동: 저장 → 제품 상세·원가 기준 / 취소 → 샴푸 제품 목록
- **방문별 사용량·추가 청구** (사장님 · 등록 · 확장 설계)
  - 목적: 사용 제품·원액 사용량과 별도 안내한 추가금을 기록합니다.
  - 규칙: 일반 샴푸를 무조건 추가 요금으로 청구하지 않습니다. 원가와 청구 근거를 구분합니다.
  - 이동: 사용 기록 저장 → 제품 상세·원가 기준 / 취소 → 제품 상세·원가 기준
- **제품 사용 중지 확인** (사장님 · 확인 · 확장 설계)
  - 목적: 신규 선택에서 제외할 제품을 확인합니다.
  - 규칙: 기존 방문 사용 기록과 구매 비용은 유지합니다.
  - 이동: 사용 중지 확정 → 샴푸 제품 목록 / 유지 → 제품 상세·원가 기준

### 예약부터 미용 완료까지

오늘의 예약을 확인하고, 아이의 관리 기록과 결제를 함께 마무리합니다.

- **예약 캘린더** (사장님 · 첫 화면 · 기존 구현 기반)
  - 목적: 날짜마다 예약 건수와 금액을 한눈에 확인합니다.
  - 규칙: 날짜를 선택하면 당일 일정이 열립니다. 새 예약은 + 버튼에서만 시작합니다.
  - 이동: 11월 6일 일정 보기 → 하루 일정 / + 예약 등록 → 예약 등록
- **하루 일정** (사장님 · 목록 · 기존 구현 기반)
  - 목적: 시간순 예약과 미용·결제 상태를 확인합니다.
  - 규칙: 목록의 예약을 선택해 상세로 이동합니다. 닫기는 패널 닫기이며 예약 취소와 구분합니다.
  - 이동: 09:00 몽이 예약 보기 → 방문 상세 / + 예약 등록 → 예약 등록 / 달력으로 → 예약 캘린더
- **예약 등록** (사장님 · 등록 · 기존 구현 기반)
  - 목적: 보호자·반려견을 검색하고 방문 시간과 요금을 정합니다.
  - 규칙: 검색 결과는 보호자명 | 반려동물명 | 전화번호 뒤 4자리입니다. 확정된 입력만 예약 목록에 추가합니다.
  - 이동: 예약 등록 → 하루 일정 / 작성 취소 → 하루 일정
- **방문 상세** (사장님 · 조회 · 기존 구현 기반)
  - 목적: 반려견·보호자 정보, 주의사항과 이번 방문의 내용을 확인합니다.
  - 규칙: 미용 기록과 금액을 구분합니다. 예약 취소는 별도의 확인 단계를 거칩니다.
  - 이동: 미용 기록 작성 → 미용 전·후 기록 / 미용 완료 · 결제 → 미용 완료 · 결제 / 예약 취소 → 예약 취소 확인 / 일정 목록 → 하루 일정
- **미용 전·후 기록** (사장님 · 수정 · 기존 구현 기반)
  - 목적: 전후 사진, 미용 소견, 보호자가 챙길 내용을 작성합니다.
  - 규칙: 기록 저장과 고객 공개는 별개입니다. 공개할 내용만 연결된 보호자의 미용수첩에 전달합니다.
  - 이동: 기록 저장 → 방문 상세 / 고객 공개 확인 → 고객 공개 확인 / 작성 취소 → 방문 상세
- **고객 공개 확인** (사장님 · 공개 · 기존 구현 기반)
  - 목적: 고객에게 보일 관리 기록을 확인하고 공개합니다.
  - 규칙: 내부 메모와 결제 내역은 고객 공개 대상이 아닙니다. 연결된 보호자만 자신의 반려견 기록을 볼 수 있습니다.
  - 이동: 고객에게 공개 → 방문 상세 / 수정으로 돌아가기 → 미용 전·후 기록
- **미용 완료 · 결제** (사장님 · 처리 · 기존 구현 기반)
  - 목적: 최종 금액과 결제 수단, 실제 결제일을 확인합니다.
  - 규칙: 결제 기록은 한 번만 반영합니다. 미용 소견 저장과 결제 처리는 독립된 작업입니다.
  - 이동: 완료 · 결제 기록 → 완료된 방문 / 돌아가기 → 방문 상세
- **완료된 방문** (사장님 · 결과 · 기존 구현 기반)
  - 목적: 기록한 결제와 미용 내용을 다시 확인합니다.
  - 규칙: 완료 금액은 장부에 반영됩니다. 이후 요금표를 변경해도 이 방문의 결제 금액은 유지됩니다.
  - 이동: 일정 목록으로 → 하루 일정 / 미용 기록 보기 → 고객 공개 확인
- **예약 취소 확인** (사장님 · 확인 · 기존 구현 기반)
  - 목적: 취소할 예약을 확인합니다.
  - 규칙: 취소를 눌렀다고 즉시 삭제하지 않습니다. 취소 이력과 결제 기록은 구분합니다.
  - 이동: 예약 유지 → 방문 상세 / 예약 취소 확정 → 하루 일정

### 요금표 관리와 버전 복원

목록에서 시작해 조회·수정하고, 변경 이력을 비교한 뒤 안전하게 복원합니다.

- **요금 분류 목록** (사장님 · 목록 · 기존 구현 기반)
  - 목적: 등록된 분류를 검색하고 선택합니다.
  - 규칙: 메뉴를 열면 목록부터 표시합니다. 등록 버튼을 눌러야 작성이 시작됩니다.
  - 이동: 소형견 미용 보기 → 요금 분류 상세 / + 섹션 등록 → 새 섹션 등록 / 변경 이력 → 요금표 변경 이력
- **요금 분류 상세** (사장님 · 조회 · 기존 구현 기반)
  - 목적: 고객에게 적용 중인 서비스·체중별 표를 읽습니다.
  - 규칙: 조회 중에는 금액 입력창이 없습니다. 수정과 삭제는 명시적인 버튼으로 구분합니다.
  - 이동: 분류 수정 → 요금표 수정 / 분류 삭제 → 분류 삭제 확인 / 목록으로 → 요금 분류 목록
- **새 섹션 등록** (사장님 · 등록 · 기존 구현 기반)
  - 목적: 새 견종 분류나 고양이·추가 요금 항목을 만듭니다.
  - 규칙: 작성 취소는 현재 요금표를 바꾸지 않습니다. 등록 후 저장하면 새 버전이 만들어집니다.
  - 이동: 섹션 저장 → 요금 분류 목록 / 작성 취소 → 요금 분류 목록
- **요금표 수정** (사장님 · 수정 · 기존 구현 기반)
  - 목적: 금액과 설명을 수정하고 변경 사유를 남깁니다.
  - 규칙: 저장 성공 시 목록으로 돌아갑니다. 다른 기기에서 먼저 수정했으면 초안을 유지하고 덮어쓰기를 막습니다.
  - 이동: 요금표 저장 → 요금 분류 목록 / 목록으로 돌아가기 → 변경사항 폐기 확인 / 동시 수정 충돌 보기 → 저장 충돌
- **변경사항 폐기 확인** (사장님 · 확인 · 기존 구현 기반)
  - 목적: 미저장 내용을 버릴지 결정합니다.
  - 규칙: 확인 전에는 입력 내용이 유지됩니다.
  - 이동: 계속 수정 → 요금표 수정 / 변경 버리고 목록으로 → 요금 분류 목록
- **저장 충돌** (사장님 · 예외 · 기존 구현 기반)
  - 목적: 다른 화면에서 먼저 저장한 변경을 덮어쓰지 않습니다.
  - 규칙: 입력은 남겨두고 저장만 중단합니다. 최신 내용을 다시 확인한 뒤 수정해야 합니다.
  - 이동: 초안으로 돌아가기 → 요금표 수정 / 최신 목록 확인 → 변경사항 폐기 확인
- **요금표 변경 이력** (사장님 · 목록 · 기존 구현 기반)
  - 목적: 버전·기록 시각·변경 사유를 확인합니다.
  - 규칙: 기존 저장본부터 보존합니다. 이미 덮어쓴 과거 데이터는 재구성하지 않습니다.
  - 이동: v1 내용 보기 → 버전 상세 · 비교 / 요금 목록으로 → 요금 분류 목록
- **버전 상세 · 비교** (사장님 · 조회 · 기존 구현 기반)
  - 목적: 그때의 전체 요금표와 변경 전후 값을 확인합니다.
  - 규칙: 과거 버전은 읽기 전용입니다. 현재 내용을 바꾸려면 복원 확인을 거칩니다.
  - 이동: 이 버전으로 복원 → 복원 영향 확인 / 이력 목록 → 요금표 변경 이력
- **복원 영향 확인** (사장님 · 확인 · 기존 구현 기반)
  - 목적: 현재 표에서 무엇이 달라지는지 확인합니다.
  - 규칙: 복원도 새 버전입니다. 기존 예약·결제 금액은 유지합니다. 이미지 장식과 예약 시간 설정은 복원 대상이 아닙니다.
  - 이동: 복원 확정 → 복원 완료 / 복원 취소 → 버전 상세 · 비교
- **복원 완료** (사장님 · 결과 · 기존 구현 기반)
  - 목적: 현재 적용 버전과 남아 있는 이력을 확인합니다.
  - 규칙: v1 내용을 복원하면 v3가 추가됩니다. v1과 v2는 삭제되지 않습니다.
  - 이동: 변경 이력 보기 → 요금표 변경 이력 / 요금 목록으로 → 요금 분류 목록
- **분류 삭제 확인** (사장님 · 확인 · 기존 구현 기반)
  - 목적: 삭제 대상과 고객 화면에 미칠 영향을 확인합니다.
  - 규칙: 삭제도 이력에 남습니다. 해당 분류의 새 예약 견적은 사용할 수 없지만 기존 예약 기록은 유지됩니다.
  - 이동: 유지하기 → 요금 분류 상세 / 분류 삭제 확정 → 요금 분류 목록

### 공지 작성과 고객 공개

공지 목록에서 작성·상세·수정·삭제를 구분하고 고객 공개를 선택합니다.

- **공지 목록** (사장님 · 목록 · 기존 구현 기반)
  - 목적: 공개·비공개 공지를 검색하고 관리합니다.
  - 규칙: 메뉴를 눌러도 작성 폼이 바로 열리지 않습니다.
  - 이동: 11월 휴무 안내 보기 → 공지 상세 / + 공지 쓰기 → 새 공지 쓰기
- **공지 상세** (사장님 · 조회 · 기존 구현 기반)
  - 목적: 공지 본문과 공개 상태를 확인합니다.
  - 규칙: 고객에게 공개된 공지는 고객 홈에서도 보입니다.
  - 이동: 공지 수정 → 공지 수정 / 공지 삭제 → 공지 삭제 확인 / 공지 목록 → 공지 목록
- **새 공지 쓰기** (사장님 · 등록 · 기존 구현 기반)
  - 목적: 제목·본문을 작성하고 공개 여부를 선택합니다.
  - 규칙: 저장하기 전에는 고객 화면에 반영하지 않습니다.
  - 이동: 공지 저장 → 공지 목록 / 작성 취소 → 공지 목록
- **공지 수정** (사장님 · 수정 · 기존 구현 기반)
  - 목적: 본문이나 공개 상태를 변경합니다.
  - 규칙: 저장 후에만 고객 화면이 변경됩니다.
  - 이동: 수정 저장 → 공지 상세 / 작성 취소 → 공지 상세
- **공지 삭제 확인** (사장님 · 확인 · 기존 구현 기반)
  - 목적: 삭제할 제목과 공개 상태를 확인합니다.
  - 규칙: 삭제 확정 후 고객 화면에서도 사라집니다.
  - 이동: 공지 유지 → 공지 상세 / 삭제 확인 → 공지 목록
