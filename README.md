# 몽글 · 우리 가게의 다정한 기록

1인 애견미용사의 고객관리대장, 예약, 샴푸 사용 비용, 결제 기록, 수입·지출을 한곳에서 관리하는 웹앱입니다. React·TypeScript 화면과 Python 표준 라이브러리·SQLite 서버로 구성합니다.

## 첫 버전에서 하는 일

- 보호자·반려견 정보, 서비스, 날짜·시간, 소요 시간, 예상 금액으로 예약 등록
- 보호자별 여러 반려견 등록, 견종·몸무게·생년월일·주의사항·선호 스타일 관리와 예약 이력 조회
- 서비스 기본가·시간, 견종별 추가금, 체중 구간별 추가금을 요금표에서 설정
- 예약마다 입질·엉킴·추가 작업 등의 사유와 추가금 기록, 정산 전 견적 조정
- 샴푸 제품·기준 구매금액·용량 등록, 예약별 원액 사용량·추정 원가·고객 추가요금 기록
- 겹치는 예약 방지, 미결제 예약 수정·취소
- 카드·현금·계좌이체 결제 기록과 실제 결제일 기준 매출 집계
- 지출 기록과 월별 매출·지출·차액 확인
- 장부 CSV 내보내기

예약 금액은 결제 전까지 매출에 포함하지 않습니다. 화면의 수익은 **기록한 결제액에서 지출을 뺀 현금 흐름상 차액**이며, 세금·감가상각 등을 반영한 회계상 순이익이 아닙니다. 카드 수수료 등의 비용은 별도 지출로 기록합니다.

견적은 **서비스 기본가 + 견종 추가금 + 체중 추가금 + 사유별 추가요금 + 샴푸 고객 추가요금**으로 구성합니다. 요금표의 초기 서비스는 예시이며 견종·체중 규칙은 비어 있으므로, 사용 전에 매장 요금에 맞게 설정합니다. 저장한 예약에는 당시 견적 내역이 남아 이후 요금표 변경으로 금액이 바뀌지 않습니다.

샴푸 사용 원가는 `기준 구매금액 ÷ 원액 용량(mL) × 사용 원액량(mL)`으로 계산한 참고 비용입니다. 실제 샴푸 구매비는 **샴푸 구매 지출로 따로 기록**하고, 사용 원가는 장부에서 다시 차감하지 않습니다. 희석 비율은 제조사 지침을 확인해 기록하는 항목이며 원가 계산에 적용하지 않습니다. `0`은 비율 미등록을 뜻하며, 앱이 사용법을 추천하는 값이 아닙니다.

## 링크로 공유하는 체험판

공유용 체험판은 Python 서버 없이 실행되며 가상 예시 데이터로 기능을 시험할 수 있습니다. 같은 URL을 열어도 **방문자마다 자기 브라우저에 따로 저장**되므로 다른 사람의 기록이나 다른 기기의 기록과 동기화되지 않습니다. 실제 고객 정보는 입력하지 마세요.

```bash
npm ci
npm run test:demo
npm run package:demo
```

체험판은 **GitHub Pages**로 공유합니다. 원본 코드는 `main`, 빌드한 웹 파일은 `gh-pages` 브랜치에서 관리합니다. 최초 게시 시 [저장소의 Pages 설정](https://github.com/MaHyuna/toy_diary/settings/pages)에서 **Deploy from a branch → gh-pages → /(root) → Save**를 선택합니다. 게시 후 주소는 `https://mahyuna.github.io/toy_diary/`입니다. 브랜치 업로드와 실제 사이트 게시 완료는 별개이며, GitHub의 배포 성공 표시와 주소 접속으로 확인합니다.

`package:demo`는 `build:demo`로 화면을 빌드하고 Python으로 `artifacts/mongle-demo.zip`을 만듭니다. ZIP은 다른 정적 호스팅에도 올릴 수 있습니다. 자세한 설정과 확인 방법은 [체험판 배포 안내](docs/DEPLOYMENT.md)를 참고하세요.

## 매장용 로컬 실행

Node.js 22.12 이상과 npm, Python 3.10 이상이 필요합니다. 클라우드에서는 Node.js 24와 Python 3.12로 검증했습니다. 저장소 루트에서 실행합니다.

```bash
npm ci
npm run build
python -m server.app --host 127.0.0.1 --port 3000
```

서버가 빌드된 화면과 API를 함께 제공합니다. 로컬 브라우저에서 포트 3000으로 접속합니다. 건강 상태 확인은 `GET /api/health`를 사용합니다.

화면을 개발할 때는 서버를 켠 상태에서 별도 터미널을 엽니다.

```bash
npm run dev
```

Vite 개발 서버는 포트 5173을 사용하며 `/api` 요청을 포트 3000으로 전달합니다.

## 확인 명령

```bash
npm test
npm run build
```

`npm test`는 `python -m unittest discover -s tests -v`를 실행합니다.

## 데이터와 운영 범위

로컬 서버판 데이터는 `data/grooming.sqlite`에 저장되고 Git 추적에서 제외됩니다. 처음 실행하면 예약·결제·지출 기록이 없는 빈 장부에서 시작합니다. 데이터 보존이 필요하면 서버를 종료한 뒤 `data` 디렉터리를 별도 위치에 백업합니다. 체험판은 별도로 브라우저에 저장되며 사이트 데이터 삭제 시 테스트 기록도 지워집니다.

첫 버전은 **본인 컴퓨터에서 사용하는 단일 매장 관리 도구**입니다. 로그인, 직원별 권한, 환불, 세금 신고, 자동 백업, 네이버 예약 연동은 아직 제공하지 않습니다. 결제 완료된 예약은 금액과 결제 기록의 일관성을 위해 수정·취소할 수 없습니다. 고객대장 연결이 없던 과거 예약을 반려견 이력에 연결하는 작업은 기존 예약·금액 기록을 보존합니다. 실제 고객 정보를 여러 기기나 인터넷에서 공유하기 전에는 인증·접근 제어·HTTPS·백업 기능을 추가해야 합니다.

현재 담당자는 운영자 한 명이며 예약에 담당자 ID를 저장합니다. 직원이 늘어나면 담당자별 일정과 권한을 추가할 수 있도록 구분하되, 직원 관리 화면은 후속 개발 범위입니다.
