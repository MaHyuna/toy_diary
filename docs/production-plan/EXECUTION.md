P0의 분석·시안은 이번 산출물이다. 나머지를 진행/완료한 것으로 표시하지 않는다. P1/P2 일부 설계는 병행 가능하지만, 데이터·권한·백업 완료 전 실고객 공개는 하지 않는다. 공급자 계약이나 개인정보/운영 결정을 코드 작업 완료로 대신하지 않는다.

## 첫 구현 작업의 권장 크기

- **작업 A — 이관 안전망:** 버전형 마이그레이션 스크립트 + 사본 대조 보고서. 테스트는 샘플/임시 DB만 사용.
- **작업 B — 가격 계약:** 기존 두 요금 원본을 자동 덮어쓰지 않고 매핑표/서버 계산/불변 견적 버전부터 구현. 대표 견종·무게 경계·특수컷·상담 가격 인수 사례 포함.
- **작업 C — 운영 경계:** 기존 endpoint 계약을 유지한 HTTP 어댑터/세션 저장소/프로세스 설정/헬스·준비 상태. 기존 Store 분리 범위 이상으로 재작성하지 않음.
- **작업 D — 백업 훈련:** DB+미디어+manifest를 새 임시 환경에 복원해 검수. 결과와 소요 시간을 남김.
- **작업 E — 공통 UI 한 흐름:** 예약 달력→고객 검색→등록→상세부터 교체. 기능을 늘리기보다 동일 동작과 오류/포커스 보존을 검증.

각 작업은 목적·영향 데이터·검증·되돌리기·미해결 항목이 있는 작은 변경 단위로 리뷰한다. 데이터 변경과 광범위한 CSS 교체를 한 변경에 섞지 않는다.

## 운영 컷오버 절차

1. **대상 식별:** 신뢰할 SQLite/자료의 소유자·경로·시간을 확인. 체험 localStorage는 원장으로 간주하지 않는다.
2. **사본 리허설:** 원본 읽기 보존 → 백업 → 마이그레이션 → 대조 → 복원 훈련. 오류 항목은 별도 보고하며 삭제/추정 보정 금지.
3. **배포 준비:** 운영 도메인/HTTPS·영속 디스크·운영 계정·원격 백업·알림·복구 담당자와 중단 시간 확보.
4. **쓰기 동결:** 구 기록원의 신규 쓰기 중단 → 최종 일관 백업/manifest → 검수된 마이그레이션 → 대조.
5. **검수:** 날짜/수단별 결제 합계, 예약 건수·겹침, 고객-아이 연결, 공개본/사진 샘플, 사장님/보호자 권한 확인.
6. **오픈:** 사장님 기기부터 접속·소량 검증. 고객 기능은 별도 게이트 후 공개. 구 자료는 읽기 전용으로 유지.
7. **중단/롤백:** 대조 불일치·사진 누락·타인 정보 노출·중복 결제는 즉시 쓰기 중지. 컷오버 이후 추가 기록을 보존한 뒤 코드/DB 호환 범위에 맞게 복원 또는 전진 수정. 이전 DB를 그냥 덮어쓰지 않는다.

## 확인해야 할 운영 결정

진행을 막기 위해 질문을 반복하기보다 다음 설계/구현 착수 시 필요한 항목을 모은다.

- 실제 데이터 원본이 있는지와 수량(예약/사진/연락처) — 이번 분석은 실제 DB를 열람하지 않았음.
- 매장 영업시간·미용 동시 수용 수·휴식/버퍼·고객 신청 확정 방식·신청 보류 만료 시간.
- 실제 서비스/컷/견종 분류/체중 경계, 상담 가격, 할인/추가금·환불/부분결제 필요성.
- 도메인 소유 여부, 호스팅/백업 예산, 운영/복구 담당자, 허용 중단/손실 시간.
- 보호자 본인 확인·계정 복구 방식, 사진 공개 동의·자료 보관 기준.

공급자 요금·SLA·최신 정책은 계정/서비스 선택 시 별도 확인한다. 외부 서비스가 연결됐다고 가정하지 않는다. 네이버 예약·전국 평균요금 API·PG 결제·SMS/OAuth는 현재 연동 완료 상태가 아니다.

## 이번 분석의 검증 범위

- 코드·배포 문서·테스트를 읽고 현재/제안/공백을 구분했다.
- 기존 서버 자동 테스트는 임시 DB로 실행했다(이번 확인: 68개 통과).
- 시안은 별도 HTML이며 화면 전환/모바일 오버플로 검증을 진행한다. 실제 서비스 인증/견적/저장을 연결한 통합 검증은 아니다.
- 운영 DB·연락처·사진은 열람/수정하지 않았다. 앱 기능 코드와 Pages 배포는 이번 작업 범위에서 변경하지 않는다.
