# 요금표 버전 이력

## 업무 동선

요금 관리 목록 → 변경 이력 → 버전 상세(직전 버전과의 차이, 당시 전체 표) → 복원 영향 확인 → 복원 확정 → 현재 목록.

수정 시 변경 사유는 선택 입력이다. 저장할 때 요금표 전체를 새 버전으로 보존한다. 분류 삭제도 동일한 저장 경로를 지나므로 삭제 전 내용을 복원할 수 있다. 같은 내용을 반복 저장하면 불필요한 버전을 만들지 않는다. 복원은 대상이 동일한 내용이어도 새 버전이며 복원 출처를 기록한다. 이력 수정·삭제 API는 제공하지 않는다.

## 보존 범위와 제한

- 요금표의 서비스 열, 분류, 견종 설명, 체중 행, 금액 문자열, 추가 항목과 안내문 전체.
- 버전 번호, UTC 기록 시각(화면은 한국 시간), 저장/기존본 보존/복원 구분, 변경 사유, 복원 출처 버전.
- 비교는 행·열 위치 기준이며 순서를 바꾼 경우 해당 위치의 이름·금액 변경으로 표시한다. 이름을 추측해서 다른 항목과 합치지 않는다.
- 기존 저장본을 첫 이력으로 보존한다. 이 시각은 최초 작성일이 아니라 보존 시작 시각이다. 이미 덮어쓴 과거 요금은 재생성하지 않는다.
- 게시 이미지/캔버스 장식과 예약 가능 시간·체중 연결 설정은 이 버전의 복원 범위가 아니다. 고객 화면은 현재 요금과 일치하는 이미지만 표시한다. 요금과 맞지 않는 이미지는 재게시해야 한다.
- 현재 인증은 단일 사장님 계정이므로 직원별 작성자 식별을 제공하는 것처럼 표시하지 않는다. 다중 직원 도입 시 인증 주체 ID를 감사 기록에 추가해야 한다.

## 데이터와 권한

SQLite에 `price_menu_history` 테이블을 추가한다. 기존 요금표·예약·결제 테이블을 삭제하거나 재작성하지 않는다. 시작 시 기존 요금표(구형 게시 이미지에 포함된 원본도 포함)를 한 번 보존한다. 이후 요금표를 갱신하는 기존 PUT 경로도 새 이력을 남긴다.

사장님 전용 API:

- `GET /api/price-menu/state`: 현재 요금표와 수정 기준 버전.
- `GET /api/price-menu/history?offset=0`: 최근 순 20건씩, 전체 건수와 현재 버전.
- `GET /api/price-menu/history/:version`: 읽기 전용 원본.
- `POST /api/price-menu/revisions`: `{menu, expectedVersion, note}`.
- `POST /api/price-menu/history/:version/restore`: `{expectedVersion, note}`.

현재 앱의 저장·삭제·복원은 기준 버전을 검사한다. 다르면 409로 중단하고 초안은 유지한다. 현재 요금표 변경과 이력 추가는 동일한 `BEGIN IMMEDIATE` 트랜잭션에서 처리하므로 한쪽만 저장되지 않는다. 이전 클라이언트 호환용 `PUT /price-menu`는 이력은 남기지만 기준 버전 검사는 없다. 운영 시 구형 클라이언트를 함께 사용하지 않아야 한다.

예약 및 결제 기록과 예약 신청의 기존 견적 스냅샷은 수정하지 않는다. 변경/복원은 이후 조회하는 고객 요금표와 새 예약 견적에 적용된다. 복원된 요금에 현재 예약 연결 설정이 일치하면 해당 항목의 새 견적에도 적용된다.

## Pages와 실서버

GitHub Pages에서는 각 브라우저의 기존 데이터 안에 `priceHistory`를 추가한다. 저장 실패 시 현재본과 이력 모두 유지한다. 지원 브라우저의 Web Locks로 동일 출처 탭 간 쓰기를 직렬화한다. 브라우저 저장 공간 삭제·체험 데이터 초기화 시 이력도 삭제되며 다른 기기로 동기화되지 않는다. 실제 운영 이력은 Python·SQLite 서버판과 백업을 사용해야 한다.

서버 백업은 기존 SQLite 전체 백업에 새 테이블이 함께 포함된다. 배포 전 DB 백업을 보관하고 복원 테스트를 해야 한다. 이 작업의 테스트는 임시 DB만 사용하며 실제 `data/grooming.sqlite`에는 접근하지 않았다.

## 검증

서버: 기존본 마이그레이션 재실행, 새 버전 저장/복원, 두 동시 요청의 충돌, 이력 저장 실패 시 현재본 롤백, 예약 보존, 권한, 잘못된 버전/내용 거부, 페이지 나누기.

Pages: 재접속 이력 보존, 저장 용량 실패 원자성, 여러 탭 초안 유지 및 충돌 차단, 변경 전후 조회, 복원 취소/확정, 모바일/PC, 고객 반영과 예약 보존.
