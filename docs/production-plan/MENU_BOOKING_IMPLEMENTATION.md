# 게시 요금표와 예약 견적 연결 — 구현 현황

2026-11-06. 이 문서는 이전 분석 문서의 '예약 계산은 별도 legacy pricing' 상태를 갱신한다. 새 UI 기준은 [Spectrum 2](../SPECTRUM_UI.md)다. 별도 `preview.html` 시안은 적용하지 않았다.

## 운영 방법

1. 사장님 요금 관리에서 고객에게 게시할 요금표를 저장한다.
2. 같은 화면의 '예약 요금 연결'에서 표 항목, 적용할 최소/최대 체중, 소요 시간을 지정한다. 표에 적힌 체중 문구를 자동으로 추측하지 않으므로 사장님이 실제 표와 일치하는지 확인해야 한다.
3. 연결한 항목만 고객 예약에 표시한다. 숫자 또는 정상 천 단위 구분 숫자(선택적으로 '원')인 금액만 연결된다. '상담', '7,000 / 10,000', 가격 범위는 단일 금액으로 변환하지 않는다.
4. 고객이 요금 분류·몸무게·서비스를 선택하면 게시된 표의 금액을 사용한다. 분류는 고객이 선택하며, 견종 자동 분류·추가 작업 비용 자동 산정은 하지 않는다.
5. 사장님 직접 등록은 '게시 요금표에서 불러오기 → 선택 요금 적용'으로 같은 금액·소요 시간을 사용한다. 상담 금액과 추가 작업은 기존 직접 입력 기능으로 조정한다.

연결 전에는 온라인 예약이 '준비 중'으로 표시된다. 기존 숨은 기본 요금으로 자동 대체하지 않는다. 체험의 예시 표도 먼저 저장한 뒤 연결해야 한다. 기존 예약 조회·수정·수기 등록은 계속 가능하다.

## 데이터 계약

- 게시 원본: 기존 settings `price-menu` (없으면 기존 `price-poster.menu`). 원본 구조·이미지 데이터 변경 없음.
- 새 settings `menu-booking`: 원본 위치와 분류/서비스/체중 문구, 명시적 체중 범위, 소요 시간만 저장. **금액은 중복 저장하지 않는다.**
- 행·열 이동이나 이름 변경으로 원본 식별 정보가 맞지 않거나 금액이 상담형으로 바뀌면 해당 연결은 비활성화된다. 사장님 화면에서 사용 불가 연결을 해제하고 다시 연결한다.
- 공개 `/api/public/catalog`의 `booking`에는 원본에서 계산한 offers와 revision이 있다. 이전의 별도 `pricing`은 공개 응답에서 제거했다. 기존 owner `/state`의 legacy pricing 설정은 데이터 보존을 위해 남겨 둔다.
- 공개 신청은 `serviceId`, `revision`을 필수로 사용한다. 클라이언트 금액은 받지 않는다. 서버는 쓰기 트랜잭션 안에서 현재 메뉴·연결을 읽고 버전, 체중, 시간 충돌을 재검사한다.
- 신청 도중 원본이나 연결이 변경되면 409로 재확인을 요구한다. UI는 입력한 고객 정보를 유지하면서 최신 서비스를 다시 선택하게 한다.
- 신청 레코드의 JSON payload에 `quoteSnapshot`(revision+offer)을 저장한다. 예약 승인 후에도 신청의 견적 기록은 남는다. 승인된 appointment에는 접수 당시 금액·서비스·소요 시간을 복사하며 기존 `externalId`로 신청과 연결한다.
- 사장님 수기 등록에서 요금표 불러오기는 명시적 프리필이며, 고객 신청과 같은 변경 불가 견적 스냅샷 생성으로 주장하지 않는다. 사장님이 직접 금액을 조정할 수 있다.
- `GET/PUT /api/menu-booking`은 기존 owner 인증을 요구한다. UI를 숨기는 것으로 권한을 대체하지 않는다.
- 서버/Pages adapter에 동일한 금액·범위·버전 검증 정책을 적용한다. 브라우저 체험 데이터를 실서비스 DB로 이전하는 작업은 하지 않았다.

## 보존·제한 사항

기존 DB 스키마를 삭제하거나 변경하지 않는다. settings 키 추가와 새 신청 payload 확장이다. 기존 고객·예약·결제 기록을 변환하거나 금액을 재산정하지 않는다. 운영 DB를 열거나 수정하지 않았고, 모든 서버 검사는 임시 DB로 실행했다.

최소 체중 이상, 최대 체중 미만이며 최상한 150kg만 포함한다. 같은 분류·서비스에서 체중 구간이 겹치는 연결은 거부한다. 표의 금액만 바뀌면 새로운 견적에 반영하고 기존 신청·예약에는 반영하지 않는다. 과거 신청에도 snapshot을 만들어 넣는 소급 처리는 하지 않는다.

게시 요금표의 모든 과거 버전을 보관하는 독립 버전 테이블은 아직 없다. 현재 구현은 현재 원본의 revision 검사와 신청별 견적 snapshot이다. 취소/환불, 결제 상태 분리, 고객 로그인 기반 신청 조회, 운영 서버 배포·백업은 별도 후속 작업이다. 영업시간은 기존 09:00–19:00 정책을 유지했다.

API 변경으로 예전 프런트엔드의 공개 신청 payload는 더 이상 접수되지 않는다. 실배포 시 서버와 프런트엔드를 함께 갱신하고 먼저 요금 연결을 검증해야 한다. 이전 클라이언트를 위해 잘못된 legacy 가격으로 접수하는 우회 경로는 만들지 않았다.
