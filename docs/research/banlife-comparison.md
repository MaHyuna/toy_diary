# 반려생활 공개 서비스와 몽글 비교

검토일: 2026-11-06 (한국 시간). 대상: 현재 작업 트리의 몽글, 반려생활 공식 웹 공개 페이지.

## 결론과 조사 범위

반려생활의 공개 웹은 반려동물 동반 여행·숙소 탐색과 예약을 중심으로 한다. 반려동물 조건, 가격, 추가 비용, 이용 조건을 예약 전에 확인하게 만드는 정보 구조를 참고할 가치가 있다. 그러나 **애견미용실의 사장님용 예약·고객·정산 시스템으로서 적합한지는 현재 자료로 판단할 수 없다.** 지인이 사용하는 정확한 URL은 사용자에게 확인 요청했다. 서비스명이 같다는 이유로 미용실 관리 솔루션이라고 단정하지 않는다.

공식 홈·숙소 상세·로그인의 공개 HTML을 직접 확인했다. 계정을 만들거나 실제 예약·결제를 하지 않았다. 로그인 뒤 예약 확인 화면, 관리자 달력, 정산 기능, 연동 API, 가격 정책은 확인하지 않았다. 따라서 아래는 완전한 제품 평가나 관리자 UI 벤치마킹이 아니다.

## 직접 확인한 출처

1. [공식 홈](https://www.ban-life.com/): 여행·숙소 예약 안내, 인기 여행지, 숙소별 가격·견종 크기·체중 조건·시설·후기, 숙소/가게 입점 문의. 검색 링크에는 날짜·인원·반려동물 수 등의 조건이 포함된다. 검색 기능 전부를 실제 실행해 본 것은 아니다.
2. [공개 숙소 상세 예시](https://www.ban-life.com/accommodation/20121): 시설 정보, 객실 선택, 반려동물 동반 조건, 현장 추가 비용, 예약 변경·취소 안내. 해당 숙소의 안내이지 모든 판매자의 공통 규정은 아니다.
3. [로그인](https://www.ban-life.com/login): 네이버·카카오·Google·Apple·이메일 로그인 진입점. 실제 인증 성공이나 계정 연결 정책은 미검증.

사이트의 '1등' 같은 홍보 표현을 객관적 순위나 품질 근거로 사용하지 않는다. 공개 확인으로 매장 관리 기능의 부재를 입증할 수도 없다.

## 참고할 점과 그대로 따르지 않을 점

- 조건을 가격 가까이에 배치한다. 미용에서는 몸무게, 서비스 범위, 추가 요금 사전 안내가 해당한다.
- 탐색에 필요한 사진과 업무 처리에 필요한 표는 역할이 다르다. 사진 중심 숙소 탐색을 고객·정산 표로 확대하지 않는다.
- 긴 설명을 여러 위치에 복사하지 않는다. 확인한 숙소 예시에는 체중별 추가 요금 설명이 여러 곳에 있고 표현·구간이 달랐다. 실제 청구 정책은 확인하지 못했지만, 몽글에는 요금 원본과 게시 버전을 통일해야 하는 근거가 된다.
- 신청 접수와 확정, 확정 금액과 예상 금액, 결제 기록과 실제 PG 결제를 구분한다.
- 취소 수수료·예약금·노쇼 정책을 경쟁사에서 가져와 적용하지 않는다. 매장의 운영 정책 확정이 선행돼야 한다.

## 이번에 바로 구현한 범위

`src/PublicBooking.tsx`, `src/booking.css`:

- 신청 확인을 미용 서비스 / 방문 일정 / 아이·보호자 / 예상 금액으로 구분.
- 서비스 변경, 일정 변경, 정보 수정 바로가기. 정보나 일정 수정 후 확인 화면으로 복귀.
- 서비스 변경 시 이용 가능한 시간을 다시 선택하도록 해 이전 서비스의 시간을 그대로 제출하지 않음.
- 요청사항을 확인 화면과 접수 결과에도 표시. 줄바꿈 유지, 긴 텍스트 줄바꿈 처리.
- 수정 시 개인정보 동의를 다시 확인하도록 체크 해제.
- 단계 이동 시 제목에 키보드 초점 이동. 수정 버튼 터치 영역 44px 이상.
- 기존 색상·역할 경로·가격 계산·DB 스키마·사이트 전체 구조 보존. 개인정보를 새로 브라우저에 저장하는 기능은 추가하지 않음.

실제 서버판과 Pages용 빌드의 공통 컴포넌트 변경이다. 라이브 사이트 배포와 실서비스 서버 개설은 이 문서의 구현 완료 범위에 포함되지 않는다.

## 검증

- `npm run build`, `npm run build:demo`: 통과.
- `python tests/browser_booking_review.py`: 임시 SQLite와 실제 서버 API를 사용해 정보/일정/서비스 수정, 잘못된 체중 차단, 동의 초기화, 요청사항 보존, pending 신청 1건 저장 검증.
- 320/390/768/1440px에서 신청 확인 화면 가로 넘침 없음·수정 버튼 높이 확인. 브라우저 실행 오류 없음.
- 실제 운영 DB는 열거나 변경하지 않음. 기존 요금표 불일치 및 고객 예약 조회 문제를 이번 변경으로 해결했다고 주장하지 않음.
