# 사장님 캘린더 UX 결정안

작성: 로고스 · 기획/UX, 2026-11-05 한국 시간 기준.

이 문서는 현재 코드·사용자 피드백과 사용자가 첨부한 네이버 캘린더 화면을 바탕으로 한 개편 기준이다. 첨부 화면의 시각·동작을 참고했으며 경쟁 앱을 직접 사용한 벤치마킹이나 네이버 공식 연동을 뜻하지 않는다. 구현 및 검증 여부는 아래 수용 기준과 대조해 확인한다.

## 역할과 목표

- 로고스: 사장님이 날짜·예약·금액을 읽고 다음 행동을 결정하는 흐름과 예외 상태 정의.
- 카리스: 정보 위계, PC/모바일 레이아웃, 글꼴·색·여백·상태 디자인.
- 누스: 날짜 선택, 일정 상세, 등록·정산, 키보드 접근, 전환 피드백 구현.

PC에서는 월간 상황과 선택일 예약을 함께 보고, 모바일에서는 전체 월간과 선택일 일정을 명확하게 전환한다. 예약을 찾거나 추가한 뒤 같은 날짜의 맥락으로 돌아올 수 있어야 한다.

## 개편을 시작한 문제

- 날짜를 누를 때마다 일별 모달이 월간 달력을 가려 날짜 비교가 불편했다. 일별 모달을 제거하고 PC는 옆 패널, 모바일은 선택주 아래 인라인 일정으로 바꾼다.
- 높은 제목·반복 설명·큰 금액 카드가 실제 목록 공간을 줄였다. 작은 헤더와 구분선 중심 예약 행을 사용한다.
- 방문일의 예약 건수와 결제일의 받은 금액은 다른 기준이다. 예약이 없는 날의 결제도 설명 가능한 화면을 유지한다.

## 보존할 사용자 결정

- 사장님 첫 화면은 캘린더다. 모바일에서 설명·큰 통계 카드 때문에 첫 달력을 밀어내지 않는다.
- 날짜마다 예약 건수와 금액이 보인다. 각 셀에 반복되는 '매출' 글자는 넣지 않는다.
- 금액 전환 문구는 `받은 금액`과 `예약 금액`이다. 기본은 실제 결제일 기준 받은 금액이며 예약 금액은 방문일 기준 예상금액이다. 두 값을 합산하지 않고 운영비 차감 손익은 별도 화면에 둔다.
- 카드 제목만 누르는 동작은 유지하지 않는다. 시간·아이·서비스·금액이 있는 넓은 예약 본문이 상세 열기의 버튼이다. 수정·취소·미용 완료는 별도의 버튼이다.
- 고객 검색 결과는 `보호자명 | 반려동물 이름 | 연락처 끝 4자리` 순서다. 전체 번호는 선택 후 예약 정보에 채워진다.
- 캔버스·예약 모두 드래그로 위치를 바꾸는 기능을 추가하지 않는다. 기존의 드래그 제거와 기본 배치는 보존한다.
- 고객 예약/요금 안내와 사장님 화면은 별도 진입점을 사용한다. 데모 저장 범위와 아직 연결되지 않은 네이버 상태를 바꾸지 않는다.

## PC 첫 화면

### 월간 캘린더 + 선택일 일정

충분한 가로 공간이 있는 PC에서는 왼쪽 월간 캘린더와 오른쪽 선택일 일정 패널을 동시에 표시한다. 첫 선택일은 오늘이다. 날짜를 누르면 우측의 날짜·요약·목록만 갱신하고, 새 모달로 달력을 덮지 않는다.

가로 1100px 이상에서 월간+선택일 패널을 사용하고, 그 미만은 모두 아래 모바일·태블릿의 두 모드를 사용한다. CSS와 날짜 선택 로직의 기준을 일치시킨다. PC에서는 본문 폭을 1020px에 고정하지 않고 사용 가능한 영역에 맞춘다.

PC에서 예약 등록의 주 진입점은 선택일 패널 오른쪽 아래의 작은 `＋` FAB다. 버튼의 접근성 이름으로 선택 날짜의 예약을 추가한다는 의미를 제공하며, 선택한 날짜가 채워진 폼을 연다. 패널 상단의 넓은 등록 버튼은 제거한다. 조회 월/오늘·월 이동·금액 기준을 간결하게 정렬하고 예약 신청과 채널은 상단 아이콘 도구로 통합한다. 별도 높은 도구 행을 쌓지 않는다.

### 날짜 셀

읽는 순서는 날짜 → 예약 건수와 금액 → 시간·아이의 짧은 예약 미리보기다.

- 예약 미리보기는 최대 2–3개만 표시하고 초과 건수는 `+N건`으로 표시한다. 셀 밖으로 흘러나오지 않는다.
- 미리보기와 금액은 조회 중인 기준을 설명하기 위한 정보다. 셀 안에 결제·취소 같은 데이터 변경 버튼을 넣지 않는다.
- 셀 한 번 클릭은 해당 날짜 선택이다. 빈 날짜도 선택할 수 있다.
- 오늘은 날짜 숫자의 원형 표시, 선택일은 셀 테두리·배경으로 구분한다. 오늘과 선택일이 겹쳐도 두 신호가 유지돼야 한다.
- PC에서 긴 보호자 이름·견종 전체를 날짜 셀에 넣지 않는다. 일별 패널과 상세 화면에 맡긴다.
- 큰 금액을 줄여 표시하더라도 접근성 이름 또는 툴팁에는 전체 금액을 제공한다.

## 선택일 일정 패널

### 상단은 한 줄, 목록은 넓게

상단은 월일·요일, 예약 건수, 이전/다음 날짜 버튼을 한 줄에 배치한다. 일반적인 PC 뷰포트에서 높이 60–72px를 목표로 하며, 고정 헤더 전체는 패널 높이의 20% 이하로 유지한다. 예약 목록을 확인하는 스크롤 뷰포트는 패널 높이의 80% 이상을 확보한다.

'선택한 일정', 날짜, 'N건의 예약', 완료/대기 문장처럼 같은 맥락을 여러 줄로 반복하지 않는다. 완료 상태는 각 예약 행에서 확인한다. 결제 금액과 예약 예상은 두 개의 큰 카드 대신 스크롤 본문 앞의 작은 금액 행에서 구분한다. 결제일/방문일 기준을 설명할 필요가 있을 때는 접근성 이름·툴팁 또는 필요한 순간의 안내를 사용하며, 설명 문장을 상시 여러 줄 쌓지 않는다.

일정은 시간순 행을 기본으로 한다. 각 행은 시간·아이·서비스·금액을 빠르게 비교할 수 있어야 한다. 예약마다 큰 모서리 둥근 카드와 높은 설명 영역을 반복하지 않으며, 구분선·간격·상태로 묶는다.

스크롤 공간은 상단 구조와 반복 설명을 줄여 확보한다. 글자 크기나 버튼의 실제 조작 영역만 줄이는 방식으로 목표 비율을 맞추지 않는다.

각 예약의 본문에는 시간, 아이 이름, 서비스, 보호자 요약, 예상/결제 상태와 금액을 배치한다. 눌러서 더 볼 수 있다는 단서를 제공하되 '상세 보기' 문구가 시간·아이 이름보다 강조되지 않도록 한다.

1. **상세 확인:** 넓은 본문 클릭 또는 키보드 Enter로 상세를 연다. 닫으면 같은 날짜·선택 맥락을 유지한다.
2. **등록:** 패널 오른쪽 아래 `＋`는 현재 선택일이 채워진 폼을 연다. 날짜를 바꾼 뒤에도 방금 선택한 날짜를 사용하며, 등록 버튼을 누르기 전에는 폼이 열리지 않는다. 저장 성공 뒤 목록과 월간 건수·금액을 함께 갱신한다. 실패 시 폼을 유지하고 이유를 표시한다.
3. **수정:** 기존 예약·연결 고객·제품 사용량을 유지한 폼을 연다. 정산 완료된 기록은 기존 수정 제한을 유지한다.
4. **결제 기록:** 등록·상세와 시각적으로 구분한다. 예약을 단순히 선택하거나 상세를 열었다는 이유로 완료·결제 기록을 만들지 않는다. 대상·작업·최종 금액을 확인하고 결제 수단과 실제 결제일을 명시적으로 기록한다.
5. **취소:** 상세 열기와 독립된 액션으로 제공하고 확인 절차를 유지한다. 취소한 예약은 확정 건수와 예약 예상에서 제외한다.

PC 일정 목록이 길면 패널 내부에서 스크롤하고 월간 달력과 한 줄 날짜 헤더는 유지한다. 오른쪽 아래 `＋`는 스크롤 위치에 관계없이 찾을 수 있게 유지한다. 목록 하단에는 버튼 높이와 안전 간격을 합친 스크롤 여백을 두어 마지막 예약의 내용·상세 버튼·수정/취소/정산 액션이 FAB 아래에 가리지 않도록 한다. 패널 내용을 새로 고칠 때 이전 날짜의 목록이 새 날짜 제목 밑에 남지 않도록 한다.

## 방문 상세는 아이·보호자·작업 맥락을 먼저 보여주기

예약 상세는 금액만 확인하는 화면이 아니다. 다음 순서로 읽히게 한다.

1. **방문 대상과 일정:** 아이 이름·사진, 보호자 이름·연락처, 방문 날짜·시간, 서비스와 소요 시간. 연결된 고객이 없어도 예약 당시 저장된 정보를 표시한다.
2. **이번 방문 작업:** 요청 스타일과 방문 메모를 확인·수정할 수 있다. 빈 메모는 짧게 표시하고 작성 진입점을 제공한다.
3. **아이 대장 참고사항:** 연결된 반려견의 알레르기·건강·행동 주의점과 선호 스타일을 출처가 드러나는 영역에서 보여준다.
4. **보호자 대장 메모:** 보호자에게 연락할 때 참고할 메모를 아이의 건강·행동 기록과 섞지 않는다.
5. **금액과 사용 제품:** 합계는 식별 가능하게 두되 세부 산출 근거와 샴푸 원가는 필요한 경우 펼쳐 확인한다. 내부 원가와 고객 청구액의 의미를 구분한다.

예약 당시의 이름·연락처·견적은 방문 기록의 스냅샷이다. 연결된 고객대장의 현재 참고사항을 보여주기 위해 과거의 예약 이름·가격을 자동으로 덮어쓰지 않는다. 대장이 연결되지 않았으면 예약 정보를 그대로 사용하며 존재하지 않는 메모나 건강 정보를 만들어 넣지 않는다. 예약 연락처와 현재 고객대장 연락처가 다르면 출처를 구분하여 추가 표시한다.

방문 메모 저장은 `appointment.notes`만 바꾼다. 고객대장 메모·건강 정보·선호 스타일을 함께 변경하지 않는다. 정산/취소 기록에도 notes-only PATCH를 허용하되 금액·예약일·상태 등 기존 잠금은 유지한다. 편집 취소는 초안을 폐기하고, 저장 실패 시 작성 내용을 남겨 다시 저장할 수 있게 한다. 메모를 보거나 수정하는 동작이 결제·고객 공유를 발생시키지 않는다.

## 결제 기록 흐름

### 대상 확인 → 수단 선택 → 명시적인 기록

결제 화면에서도 아이·보호자·방문 서비스와 작업 내용을 먼저 확인한다. 합계 숫자만 크게 띄워 누구의 어떤 방문을 처리하는지 놓치게 하지 않는다.

- 아이 이름·사진과 보호자 이름·연락처를 표시한다. 내부 관리 화면의 연락처는 전화 동작을 제공할 수 있다.
- 서비스·방문 날짜·시간과 이번 방문 메모를 확인한다. 필요한 작업 메모는 결제와 함께 저장할 수 있다.
- 기본 화면은 최종 금액, 카드/현금/계좌이체 3개 수단, 오늘 결제일, 메모와 기록 버튼으로 구성한다. 이미 선택한 값과 저장 전의 값을 분명하게 구분한다.
- 결제일은 한국 시간의 오늘이 기본이다. 매번 날짜 입력기를 노출하지 않고 `날짜 변경`을 눌렀을 때만 입력기를 표시한다. 미래 결제일은 허용하지 않는다.
- 금액 산출 내역과 기본 미용요금·엉킴/입질 등 추가 작업 요금 편집은 `요금 수정` 안으로 접어 둔다. 변경하면 합계를 즉시 다시 보여준다. 견종·몸무게 등 기존 방문의 요금 스냅샷을 현재 요금표로 자동 재계산하지 않는다.
- 최종 기록 버튼의 의미는 실제 결제 확인이다. 폼 열기·수단 선택·날짜 변경·메모 입력만으로 정산하지 않는다. 미결제 방문과 결제가 끝난 방문을 문구와 상태로 구분한다.

### 서버와 데이터 계약

`POST /appointments/:id/settle`은 `paymentMethod`, `paidDate`와 선택적인 `changes: { basePrice, extraCharges, notes }`를 받는다. 기본요금·추가요금·메모 변경을 기존 예약 검증 규칙으로 검증하고 같은 DB 트랜잭션에서 완료 처리한다. 요금 변경만 먼저 저장된 뒤 결제 기록이 실패하는 부분 저장을 만들지 않는다. 할인·음수 추가금·미수금·분할 결제·환불·실제 PG 결제는 이번 범위로 표시하지 않는다.

- **성공:** 한 번만 결제 기록을 만들고 선택일 일정과 결제일 기준 금액을 갱신한다. 완료한 기록은 다시 미결제처럼 보이지 않아야 한다.
- **중복 입력:** 기록 중 버튼을 비활성화하고 중복 제출을 막는다. 서버도 이미 결제한 예약의 재정산을 거부해 금액이 두 번 합산되지 않게 한다.
- **검증/저장 실패:** 수단·날짜·요금 수정·메모 초안을 보존하고 해당 화면에서 이유를 보여준다. 실패를 성공으로 표시하거나 폼을 닫지 않는다.
- **미결제/완료:** 미용 작업의 완료와 실제 결제 확인을 같은 개념으로 설명하지 않는다. 현재 정산 엔드포인트의 완료 처리는 결제까지 확인하는 동작이며, 단순 방문 확인이나 상세 열기를 완료 처리로 사용하지 않는다.
- **기록 후 수정:** 금액·일정·상태 잠금은 유지한다. 메모만 수정하는 동작은 별도의 notes-only 경로로 처리한다.

결제 확인과 메모 수정은 같은 디자인 토큰과 폼·버튼·오류 상태를 사용한다. 업무에 필요한 대상·일정·작업 정보를 표시하고, 디자인 시스템 설명이나 개발용 상태를 앱 화면에 넣지 않는다.

## 빈 상태·결제만 있는 날짜·실패 상태

| 상태 | 표시와 행동 |
| --- | --- |
| 예약 없는 날 | 한 줄 헤더의 날짜를 유지하고 짧은 빈 상태 표시. 오른쪽 아래 `＋`를 등록 진입점으로 사용하며 큰 빈 상태용 버튼을 중복해서 쌓지 않음. 월간 달력 유지 |
| 예약 0건, 결제액 있음 | 결제 요약을 유지하고 이날 받은 결제 건수 또는 해당 방문 정보를 제공. 예약 없음과 금액이 함께 존재할 수 있음을 설명 |
| 모든 방문 결제 완료 | 예약을 목록에서 숨기지 않고 완료 배지와 결제 수단 표시. 결제 버튼 중복 노출 금지 |
| 대기 신청 있음 | 확정 예약과 분리된 신청 수로 표시. 확정 전 금액을 실제 매출에 합산하지 않음 |
| 로딩 | 기존 날짜를 일관되게 표시하고 작업 가능한 것처럼 보이는 가짜 빈 목록을 표시하지 않음 |
| 저장·중복 시간 오류 | 사용자 입력을 유지하고 오류를 폼 가까이 표시. 실패를 성공 토스트로 처리하지 않음 |
| 네이버 미연결 | 미연결이라는 현재 상태 표시. 자동 수집·양방향 동기화 완료처럼 보이는 애니메이션/배지 금지 |

## 인터랙션과 접근성

인터랙션은 선택 결과와 작업 결과를 분명하게 하는 데 사용한다.

- 날짜 hover, 선택 테두리, 예약 본문 hover/focus, 버튼 눌림을 제공한다. 장식 때문에 가격이나 이름이 움직이지 않도록 한다.
- 선택일 목록 전환은 짧은 opacity/작은 이동 정도로 처리한다. 월간 달력 전체를 매번 흔들거나 재등장시키지 않는다.
- 실제 저장 성공은 토스트와 데이터 갱신으로 알린다. 로딩·오류는 성공 모션과 구분한다.
- `prefers-reduced-motion`이면 불필요한 이동 모션을 생략한다.
- 날짜 버튼은 키보드로 접근 가능해야 한다. 방향키를 제공할 경우 좌/우 1일, 위/아래 7일이라는 일관된 규칙을 사용하고, 월 이동 및 포커스 대상 날짜를 함께 처리한다. 입력 필드에서 전역 단축키를 가로채지 않는다.
- 선택 변경이 폼을 자동으로 열거나 자동 저장을 발생시키지 않는다. 빠른 키 이동은 일정을 확인하는 행동이어야 한다.
- 일별 패널은 제목으로 어떤 날짜인지 알 수 있어야 하고 선택 변경을 보조 기술에 알린다. 모바일에서는 숨겨진 PC 패널의 버튼이 포커스 순서에 남지 않아야 한다.
- 인라인 일정은 모달이 아니므로 dialog 속성·포커스 가두기를 사용하지 않는다. `월간 펼치기` 후 선택한 날짜 버튼으로 포커스를 돌려준다.
- 방문 상세·등록·수정·정산은 명시적으로 여는 모달을 유지한다. Escape 닫기·포커스 가두기와 닫은 뒤 원래 예약/진입 버튼으로 복귀를 제공한다.

## 모바일과 태블릿

1100px 미만은 같은 두 모드를 사용하며 일별 모달을 열지 않는다.

- **전체 월간:** 첫 진입은 선택일이 오늘이어도 전체 월간이다. 페이지 스크롤 없이 마지막 주까지 보이고 날짜마다 건수·금액을 유지한다. PC 예약 미리보기 줄은 넣지 않는다. 날짜 탭 또는 하단 `선택한 날 일정 보기`로 선택일 모드를 연다.
- **선택일 일정:** 달력을 선택한 주 한 줄로 접고 바로 아래에 날짜·건수·작은 금액 요약과 인라인 예약 목록을 표시한다. 선택주에서도 날짜·건수·금액을 유지하고 목록 내부만 스크롤한다. `월간 펼치기`로 돌아가면 같은 선택 날짜에 포커스한다.
- 상세·폼을 열고 닫거나 저장한 뒤에는 선택주와 일정이 유지된다. 일별 모달로 되돌아가지 않으며 `＋`는 현재 선택 날짜를 사용한다.
- 320/390px, 6주 달력·높이 667px, 하단 메뉴와 안전 영역에서 날짜·금액·마지막 예약이 가리지 않는지 확인한다. 터치 영역·입력 글자만 줄여 공간을 만들지 않는다.

## 구현 수용 기준

다음은 사용성 테스트를 대신하는 출시 판정이 아니라 이번 개편의 기능·화면 검증 기준이다.

1. 1440px PC에서 월간 캘린더와 오늘 일정 패널이 첫 화면에 함께 보인다. 5주/6주 달력에서 내용이 넘치지 않는다.
2. PC 날짜 클릭은 우측 패널을 갱신한다. 1100px 미만 첫 화면은 전체 월간이며 날짜 탭/일정 보기로 선택주+인라인 일정에 진입한다. `월간 펼치기`는 선택 날짜로 포커스를 돌려주고 상세·폼 저장/닫기는 인라인 일정을 유지한다.
3. PC 날짜 셀에서 최소 시간·아이의 미리보기로 예약을 식별할 수 있다. 긴 이름, 많은 예약은 줄임/초과 건수로 처리된다.
4. 날짜 선택 → 패널 오른쪽 아래 `＋` → 해당 날짜의 예약 폼 → 고객 검색 → 저장 후 같은 날짜의 예약과 건수가 갱신된다. 취소·정산은 기존 데이터 규칙을 유지한다.
5. 예약 카드의 금액·시간을 눌러도 상세가 열린다. 수정·취소·정산 버튼은 상세 열기와 함께 실행되지 않는다.
6. `받은 금액`과 `예약 금액` 전환이 각각 결제일과 방문일 기준으로 정확하다. 예약 없는 결제일도 설명 가능한 화면이다.
7. 320px, 390px, 중간 태블릿 폭, 1440px에서 가로 넘침이 없고, 모바일 전체 월간은 페이지 스크롤 없이 보인다. 선택주에서도 건수·금액을 유지하고 날짜 칸에 '매출' 반복 라벨이 재등장하지 않는다.
8. 고객 검색 `보호자 | 반려동물 | 연락처 끝 4자리`, 샴푸 사진 선택, 고객/관리자 분리와 기존 저장 데이터가 보존된다.
9. hover·focus·선택·로딩·오류·저장 성공을 각각 구분할 수 있고, 동작 줄이기 설정에서 핵심 작업이 유지된다.

10. PC 선택일 패널의 고정 헤더는 전체 높이의 20% 이하이며, 스크롤 뷰포트는 80% 이상이다. 60–72px 한 줄 헤더를 기본으로 검증하고 낮은 PC 화면에서도 비율을 확인한다.
11. 패널 마지막 예약까지 스크롤했을 때 FAB가 아이 이름·금액·상세 열기·수정/취소/정산 버튼을 가리지 않는다. 예약이 0건·1건·여러 건인 상태 모두 확인한다.
12. 상단 설명과 큰 등록 버튼·큰 금액 카드가 재등장하지 않는다. 공간 확보를 위해 글자만 과도하게 줄이지 않았는지 실제 PC 화면과 키보드 조작으로 확인한다.

13. 상세와 결제 화면에서 아이·보호자·방문 작업의 맥락을 확인할 수 있다. 반려견/보호자 대장 메모와 이번 방문 메모를 혼동하지 않는다.
14. 결제일은 한국 시간의 오늘이 기본이고 변경 버튼을 눌렀을 때만 날짜 입력기가 나온다. 카드·현금·계좌이체의 선택 상태를 시각·접근성 속성으로 확인한다.
15. 결제 안에서 변경한 요금·메모는 검증 후 결제와 함께 원자적으로 저장된다. 잘못된 추가금·미래 날짜·중복 제출·저장 실패에서 금액이 일부만 변경되거나 초안이 사라지지 않는다.
16. 정산/취소된 방문도 메모만 수정할 수 있고 금액·일정·상태 변경은 계속 제한된다. 고객에게 공유하는 화면에 내부 대장 메모가 자동 포함되지 않는다.
