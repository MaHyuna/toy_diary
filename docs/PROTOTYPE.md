# 공유용 화면 흐름 프로토타입

주소: `/prototype/` (Pages에서는 `/toy_diary/prototype/`). 기존 서비스와 분리된 Vite 엔트리다. Claude 공유 링크는 로그인 요청만 표시되었으나 사용자가 제공한 화면 이미지로 원하는 구성을 확인했다. 화면 썸네일·화면명·경로·설명이 담긴 카드를 한 캔버스에 놓고, 행동 라벨이 달린 SVG 화살표로 연결한다. 기본은 연결형 흐름도이며 카드를 누르면 클릭형 미리보기를 연다.

- 사장님 예약 → 미용 전후 기록 → 공개 → 결제, 예약 취소 분기.
- 요금 목록 → 상세 → 등록·수정 → 이력 → 복원, 삭제·미저장 변경·저장 충돌 분기.
- 고객 홈 → 요금표 → 예약 신청 확인 → 접수, 미용수첩.
- 공지 목록 → 상세 → 작성·수정·삭제.

142개 화면, 16개 사용자 흐름. 실제 UI의 필드를 단순화한 검토용 모형이다. 자동 확정 알림은 미구현 제안으로 별도 표시한다. 온라인 예약은 요금 연결 설정을 마친 매장을 가정한다.

공식 Spectrum 2 컴포넌트는 기존 Provider를 재사용한다. 프로토타입 전용 레이아웃과 화면 모형 스타일은 `src/ui/prototype.css`에 분리했다. 일반 화면의 디자인을 교체하지 않는다.

URL fragment에 flow, screen, mode를 기록해 특정 화면을 공유하거나 새로고침·뒤로가기를 사용할 수 있다. 입력값은 React 메모리에만 남고 새로고침 시 초기화된다. API 요청·브라우저 앱 저장소 접근은 하지 않는다. 일부 예시 입력/결과만 연동하며 모든 기능의 동작 검증은 실제 서비스에서 진행한다.

검증: 모든 화면의 첫 동작 및 모든 연결 대상 유효성, 320/390/1440px 가로 넘침, 직접 화면 링크/재접속, 예시 금액 저장, 실제 API·저장소 비접근.

## 연결형 캔버스

확대·축소, 너비에 맞추기, 100% 보기와 캔버스 내부 스크롤을 제공한다. 복귀 경로는 선택적으로 점선 표시한다. 썸네일은 실제 운영 데이터가 아니라 이 프로토타입의 렌더링 화면을 캡처한 것이다. `npm run build:demo` 후 `python scripts/capture_prototype.py`, 다시 `npm run build:demo`로 정적 이미지에 반영한다. 화면과 연결 좌표는 `src/prototype/FlowBoard.tsx`에 있다.

## 운영 시나리오 확장 · 2026-11-06

전체 명세는 [SERVICE_SCENARIOS.md](production-plan/SERVICE_SCENARIOS.md)에 있다. 고객은 가입·인증·복구·탈퇴, 반려동물 등록/수정/연결, 다중 예약 항목·조건부 요청 입력·예약금·변경 재검토·취소 환불, 예약 내역·미용수첩·문의로 나눈다. 사장님은 운영 준비·영업시간·정책, 신청 검토·재검토, 방문 접수·미용·인계·노쇼, 고객/계정 연결, 정산·환불·운영비, 요금 이력, 공지, 샴푸 원가, 권한·백업, 외부 채널 검토를 다룬다.

신규 화면은 확장 설계로 표시한다. 실제 인증·예약금 PG·자동 알림·네이버 API·전체 DB 복원을 연결한 것이 아니다. 1만원 예약금과 요금은 검토용 예시이며 법적·전국 표준 요금이 아니다. 운영 정책 결정 항목은 전체 명세에 명시한다.

예약 시나리오 안에서 사장님 검토 단계에는 사장님 역할을 표시한다. 날짜/시간과 선택 항목·총액·요청은 프로토타입 메모리에서 다음 화면으로 전달한다. 변경 후 재검토는 원 검토 화면으로 돌아오며, 동일 요금의 변경에는 두 번째 예약금 결제 화면을 거치지 않는다. 필수 사유가 없으면 전송을 막고 취소는 가능하다. 운영 데이터·결제 API는 호출하지 않는다.

## 화면 미리보기 모달과 키보드

흐름도의 카드·화면 주소를 누르면 Spectrum 2 Dialog가 보드 위에 열린다. 보드를 언마운트하지 않아 확대 배율과 캔버스 스크롤을 유지한다. 닫기 버튼과 Esc로 복귀하며 처음 연 카드로 포커스를 돌린다. 모달 URL은 `mode=modal`로 공유·재접속할 수 있다. 기존 `mode=play`는 단독 화면과 명시적인 흐름도 복귀 버튼을 제공한다.

모달·단독 미리보기에서 →는 화면에 표시된 기본 동작(첫 버튼)을 실행한다. ←는 실제 방문한 이전 화면으로 돌아간다. 이동 기록이 없으면 이전 버튼을 비활성화한다. 키 입력 반복·수정키 조합과 텍스트 입력, 날짜/시간 입력, 선택 목록·표 등 내부 방향키가 필요한 영역에서는 가로채지 않는다. 필수 입력 확인은 마우스·키보드에 동일하게 적용한다. 다중 분기의 다음 동작명을 툴바에 명시한다.

## 텍스트 중심 상세 흐름도

클릭 전 카드에는 이미지를 요청·표시하지 않는다. 담당 주체(고객=초록, 사장님=파랑, 시스템 처리/상태=보라)를 카드 색과 문자로 표시한다. 확인·판단은 주황 라벨, 실패·예외는 빨강 라벨로 추가 구분한다. 시스템 색은 처리의 성격을 나타내며 화면을 볼 수 있는 권한과 구분한다.

카드는 목적, 들어오는 행동/화면, 표시·입력 항목, 처리·검증 규칙, 모든 버튼의 다음 화면/상태를 보여준다. 실제 화면에 아직 명세가 없는 항목은 업무 범위의 검토 정보로 보완하며 확장 설계 표기를 유지한다. 입력 항목의 필수 여부는 정의된 항목에만 명시한다. 카드 내용을 줄 수로 잘라 숨기지 않고, 측정한 높이에 맞춰 같은 행과 이후 행·화살표를 재배치한다. 모바일은 기본 100% 배율로 글자를 읽고 캔버스 안에서 이동한다. 제목 또는 미리보기 버튼을 누르면 기존 모달·키보드 탐색을 이용한다.

## 가독성·정보 밀도 기준

프로토타입 상단의 중복 소개를 제거하고 흐름도 진입 위치를 줄였다. 본문은 14px·행간 1.7을 기준으로 하며, 글자를 줄여 내용을 압축하지 않는다. 제목·섹션 이름·본문·보조 정보를 크기와 대비로 구분하고 카드 간 공간은 연결선과 라벨을 읽을 수 있는 범위에서 줄인다. 이 기준은 `src/ui/prototype.css`에 한정되어 기존 서비스 화면을 일괄 재작성하지 않는다.

시나리오 선택은 짧은 현재 흐름 버튼에서 Spectrum Dialog로 열린다. 검색·고객/사장님 필터·한 줄 제목과 보조 설명·현재 항목 표시를 제공한다. 선택 시 한 번 클릭으로 이동하고 닫히며, 검색 결과가 적으면 목록 높이를 줄인다. 모바일과 PC 모두 실제 열린 목록의 스크린샷으로 확인한다. 목록이나 전체 버튼 묶음을 본문에 길게 펼치지 않는다.
