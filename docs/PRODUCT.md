# 몽글 서비스 기획 · 화면 흐름 정의

[클릭해서 보는 화면 기획](https://mahyuna.github.io/toy_diary/planning/) · [시안 원본](../public/planning/index.html) · [이전 구현 상태](IMPLEMENTATION.md) · [조사 범위](RESEARCH.md)

## 1. 이 서비스가 해결하는 일

1인 애견미용사가 **예약을 받고 → 그날의 미용을 진행하고 → 금액을 확인해 결제받고 → 다음 방문에 지난 기록을 참고**하는 도구입니다. 각 단계가 같은 고객·반려견·방문 기록에 이어집니다. 미용 내용과 금액을 서로 다른 화면에 반복 입력하지 않습니다.

첫 버전은 매장 내부 관리용입니다. 보호자에게는 가격 안내표나 선택한 미용 기록 이미지만 전달합니다. 보호자가 직접 예약하는 공개 웹사이트, 직원 권한, 네이버 자동 연동은 다음 단계입니다.

### 이미 확인된 요구

- 운영자 한 명, 모바일 중심. 나중에 여러 직원으로 확장.
- 첫 화면은 스크롤 없는 월간 달력. 날짜마다 예약 건수와 미용 금액 표시.
- 오른쪽 아래에서 예약 등록. 예약 일정과 달력을 중복 메뉴로 만들지 않음.
- 보호자·견종·몸무게·미용 주의사항·과거 스타일·사진을 고객대장에 저장.
- 기본 금액에 입질·엉킴 등 실제 추가 작업 비용을 사유와 함께 반영.
- ‘미용표’는 **서비스·견종·몸무게별 가격 안내표**. 고객에게 보여주고 전달 가능.
- 정산과 매장 지출·수익 확인. 이후 네이버 예약 연동.

### 이번에 바로잡는 가정

**일반 샴푸 사용료를 기본 추가금으로 두지 않습니다.** 고객에게 기본 미용 가격을 안내하고 샴푸 구입비는 매장 운영비로 기록합니다. 제품 사용량으로 계산한 원가는 선택적인 내부 참고값이며, 고객 청구액이나 추가 현금 지출을 자동 발생시키지 않습니다.

특정 제품·스파·별도 관리가 실제 유료 서비스인지 확인되지 않았습니다. 그러한 메뉴가 매장에 존재한다면 이후 일반적인 선택 서비스로 정의합니다. 현재 기획에서 ‘샴푸를 썼기 때문에 추가 청구’하는 규칙은 제외합니다. 특정 업계의 보편적 관행으로 주장하지 않습니다.

## 2. 대표 사용자 시나리오

> 원장이 전화로 ‘두부, 비숑, 6.2kg, 토요일 10시 전체 미용’을 받는다. 달력에서 날짜를 누르고 두부를 검색한다. 지난 스타일과 발을 만질 때 예민하다는 주의사항을 확인한다. 시간과 서비스를 정하면 가격표 기준 견적이 표시된다. 예약을 저장한다. 방문 당일 미용을 진행하고, 엉킴 추가 작업이 생기면 사유·금액을 보호자와 확인해 기록한다. 완료 사진과 메모를 남긴다. 미용은 완료되었지만 결제를 아직 받지 않은 상태를 유지할 수 있다. 인계할 때 카드 결제를 기록하면 매출에 한 번 반영된다. 다음 방문 예약 시 사진과 메모를 다시 확인한다.

시나리오 금액은 설명용 예시입니다. 실제 표준가나 업계 표준 과정이 아닙니다.

## 3. 업무 흐름과 화면 연결

```mermaid
flowchart LR
  A[달력에서 날짜 선택] --> B[그날 예약 목록]
  B --> C[예약 등록]
  C --> D{기존 고객인가?}
  D -->|기존| E[반려견 검색 · 지난 기록 확인]
  D -->|신규| F[보호자 · 반려견 함께 등록]
  E --> G[서비스 · 시간 · 견적 확인]
  F --> G
  G --> H[예약 확정]
  H --> I[방문 상세 · 미용 진행]
  I --> J[작업 메모 · 사진 · 추가 작업 확인]
  J --> K[미용 완료 · 미결제]
  K --> L[최종 금액 · 결제 수단 확인]
  L --> M[결제 완료]
  M --> N[방문 이력 · 매출 기록]
  N --> O[다음 예약 잡기]
  O --> G
```

매장 가격표 준비는 예약의 선행 설정입니다. 샴푸 구매비·임대료 등 운영비 기록은 하루 업무와 별개의 보조 흐름이며, 예약마다 입력하도록 요구하지 않습니다.

## 4. 정보 구조

| 1차 메뉴 | 역할 | 포함 화면 |
| --- | --- | --- |
| 예약 | 언제 누구를 미용하는가 | 월간 달력, 날짜별 하단 목록, 예약 등록, 방문 상세 |
| 고객 | 어떤 아이이며 이전에 어떻게 미용했는가 | 고객 검색, 반려견 상세, 사진·방문 이력 |
| 장부 | 얼마를 받았고 무엇이 미결제인가 | 미용 내역, 실제 받은 금액, 운영비, 월별 차액 |
| 매장 | 반복 입력할 기준과 고객 안내 자료 | 가격 안내표, 요금 편집, 영업 설정, 선택적인 소모품 원가 |

장부 안에서 ‘미용 내역’과 ‘월별 수익’을 전환합니다. 기존의 ‘미용 장부’와 ‘운영비·손익’을 최상위 여러 메뉴로 벌리지 않습니다. ‘예약 일정’이라는 별도 페이지는 만들지 않습니다.

| P01 / 페이지 | 예약 달력 | 앱 첫 화면 | 월 이동, 날짜, 예약 건수, 견적 합계. 목록·통계·배너는 달력 아래에 붙이지 않음 | 날짜 → S01, ＋ → S02 |

| S04 / 하단 창 | 작업·금액 수정 | 방문 상세 | 스타일·메모, 사진, 실제 추가 작업 사유·금액, 수정 합계 | 저장 → P03. 금액 변경 전후 확인 |

| P08 / 페이지 | 고객용 가격 안내표 | 매장, 예약 견적의 가격 기준 보기 | 서비스·견종·체중별 요금, 적용 방식, 매장명 | 크게 보기 / 꾸미기 → P09 / 이미지 저장·공유 / 요금 편집 |
| P09 / 편집 페이지 | 요금표 꾸미기 | 고객용 가격표의 꾸미기 | 매장명·로고, 기본 스타일, 배경·포인트색, 테두리·장식, 출력 비율 | 실시간 미리보기 → PNG 다운로드 → P08 |
| S07 / 하단 창 | 요금 편집 | 가격 안내표의 편집 | 기본 서비스·시간·기본가, 견종·체중 기준 | 저장 → P08. 이전 예약 견적은 보존 |
| S08 / 하단 창 | 고객용 안내 미리보기 | 가격표·방문 상세 | 전체 가격표 또는 선택 견적. 미용 기록은 사진·안내 문구 직접 선택 | 이미지 저장 / 기기 공유. 예약·장부에는 영향 없음 |

P는 별도 페이지, S는 현재 맥락을 유지하는 하단 창입니다. 신규 등록을 위해 고객 메뉴로 나갔다가 다시 돌아오게 하지 않습니다. 하단 창 위에 여러 입력 창을 쌓지 않고 예약 초안을 유지하며 단계를 교체합니다.

## 6. 주요 화면 와이어프레임 기준

### P01 예약 달력

상단 매장명 → 월 이동 → 일~토 달력 → 하단 탭. 오른쪽 아래 예약 ＋. 날짜 칸에는 날짜, 예약 건수, 해당 방문일의 견적 합계를 보여줍니다. 합계는 **예약 금액**으로 표기하며 미래 견적을 매출이라고 부르지 않습니다. 6주 달력도 기본 모바일 세로 화면에서 탭과 ＋에 가리지 않습니다.

### S02 예약 입력

1. **누가 오나요:** 기존 반려견 검색 또는 신규 등록. 선택 시 견종·체중·최근 스타일 자동 표시.
2. **언제, 어떤 미용인가요:** 날짜·시작·소요 시간·서비스. 동일 담당자 일정 겹침 즉시 안내.
3. **예상 금액:** 가격표 기준 항목과 합계. 추가 작업은 필요할 때만 펼침.

하단에 합계와 예약 저장을 고정합니다. 사진·건강 세부 항목·샴푸 원액량을 예약 필수 입력에 넣지 않습니다. 저장 실패 시 초안 유지, 저장 중 중복 제출 방지.

### P03 방문 상세

상단 뒤로 → 반려견·보호자·시간 → **미용 전 확인할 주의사항** → 선택 서비스·견적 → 사진·작업 메모 → 상태별 주 동작. 미용 중에는 ‘작업 기록’, 미용 완료 후 미결제이면 ‘결제 확인’이 주 동작입니다. 완료 사진은 방문에 연결하고 고객대장에도 그 방문의 사진으로 모읍니다.

### P06 장부

기본은 방문별 미용 내역. 월 이동과 방문일·반려견·미용 금액·결제 여부를 확인합니다. ‘월별 수익’에서는 실제 받은 금액과 운영비를 확인합니다. 방문일 기준 금액과 실제 결제일 기준 매출을 같은 합계로 섞지 않습니다. 과거 방문을 오늘 결제하면 방문 이력은 과거 날짜에, 받은 금액은 오늘에 기록합니다.

### P08 가격 안내표

고객에게 보여줄 자료가 기본입니다. 견종 분류별 체중 행·서비스 열의 가격을 한 화면에서 읽고, 조건별 해당 칸의 금액을 설명할 수 있어야 합니다. 편집은 보조 동작입니다. 일반 샴푸를 일괄 추가금으로 안내하지 않습니다. 현장에서 추가 비용이 생기면 사유·금액을 먼저 확인하고 별도로 기록합니다.

## 7. 상태 정의와 금액 규칙

```mermaid
stateDiagram-v2
  [*] --> 예약확정
  예약확정 --> 미용중: 미용 시작
  미용중 --> 미용완료: 작업 마침
  예약확정 --> 미용완료: 시작 표시를 생략한 완료 처리
  예약확정 --> 취소: 취소 사유 기록
  미용중 --> 취소: 중단 사유 기록
  state 결제 {
    [*] --> 미결제
    미결제 --> 결제완료: 최종 금액 · 수단 · 결제일 확인
  }
```

위 그림의 미용 상태와 결제 상태는 독립된 축입니다. 미용 완료를 눌렀다고 결제를 자동 기록하지 않습니다. 결제 완료는 실제 결제 확인 동작에서만 발생합니다. 첫 범위에서는 결제 확인을 미용 완료 이후에 제공합니다. 선결제·예약금·부분 결제·환불은 별도 후속 설계가 필요합니다.

| 상황 | 처리 기준 |
| --- | --- |
| 미용은 끝났지만 보호자가 아직 오지 않음 | 미용 완료 / 미결제 |
| 사진이나 샴푸 사용량을 기록하지 않음 | 미용 완료와 결제 가능. 필수 단계가 아님 |
| 추가 작업이 생김 | 사유·추가금 기록 및 보호자 확인 여부 표시. 사전 견적을 몰래 덮어쓰지 않음 |
| 미용 시작 표시를 놓침 | 방문 상세에서 바로 미용 완료 가능. 실제 시작 시각을 추정해 만들지 않음 |
| 미결제 예약의 일정 변경 | 겹침 확인 후 변경, 금액·기존 메모 보존 |
| 취소 | 슬롯 반환, 기록 보존. 실제 결제된 건을 취소만으로 지우거나 환불 처리하지 않음 |
| 결제를 두 번 누름 | 한 번만 반영, 이미 결제된 상태 안내 |
| 결제 후 금액 정정 필요 | 첫 범위에서는 수정 잠금과 정정 미지원 안내. 이후 취소·환불 이력 설계 |
| 저장 실패 | 입력 유지, 성공 상태·매출에 반영하지 않음 |

**예상 미용 금액 = 선택한 견종 분류·체중 구간·서비스 칸의 가격 + 확인된 추가 작업 비용.** 분류별 서비스 가격을 일괄적인 기본가+추가금으로 추정하지 않습니다. 샴푸 원가를 고객 금액에 자동 더하지 않습니다. 가격표가 바뀌어도 이미 저장한 견적과 과거 결제 금액은 그대로 보존합니다.

**월별 실제 수입 = 실제 결제일에 기록한 금액 합계. 월별 차액 = 실제 수입 − 기록한 매장 지출.** 구매 지출과 참고용 사용 원가를 두 번 빼지 않습니다. 회계상 순이익·은행 잔액이라고 표현하지 않습니다.

## 8. 데이터 연결

- 보호자 → 여러 반려견 → 여러 방문. 한 방문에 예약·미용·결제 정보를 이어서 표시.
- 방문에는 예약 당시 서비스·몸무게·견적 항목, 실제 작업 메모·완료 사진, 결제 사실을 보존.
- 사진은 기본적으로 **어느 방문의 사진인지** 연결. 프로필 사진·이전 스타일 참고 사진은 별도 구분.
- 가격표는 새 예약의 기준. 방문 견적은 그때의 스냅샷.
- 매장 운영비는 방문과 별개. 제품 구매와 제품 사용량을 다른 의미로 저장.
- 고객용 공유물은 공개할 가격 또는 명시적으로 선택한 사진·안내만 포함. 연락처·건강·행동 메모는 자동 포함하지 않음.

## 9. 기존 구현과 새 기획의 차이

| 현재 구현에서 남아 있는 문제 | 새 기준 | 이행 시 유의점 |
| --- | --- | --- |
| 미용 완료와 결제를 한 동작으로 저장 | 작업 완료와 결제 확인 분리 | 기존 결제된 방문의 금액·결제일 보존 |
| 샴푸 고객 추가금 입력과 예시가 있음 | 일반 샴푸는 기본 미용에 포함, 구매는 운영비 | 과거에 저장된 실제 금액을 일괄 삭제·감액하지 않음. 새 기본 입력에서 분리 |
| 사진이 반려견에만 연결됨 | 방문별 사진 + 프로필 구분 | 기존 사진은 ‘방문 미연결’로 보존, 날짜만으로 임의 연결하지 않음 |
| 신규 고객 등록이 예약과 분리됨 | 예약 작성 중 빠른 고객 등록 | 초안 유지, 보호자 중복 생성 방지 |
| 미용 장부와 운영비 화면이 각각 있음 | 장부 안에서 내역·월별 수익 전환 | 방문일과 거래일 기준을 화면에 명시 |
| 유료 옵션을 검증 없이 일반화 | 매장 실제 서비스만 요금표에 등록 | 네트워크 조사 실패를 업계 관행으로 대체하지 않음 |

이 문서와 클릭 시안은 **새 구현 제안**입니다. 현재 앱이 위 모든 흐름을 이미 지원한다는 의미가 아닙니다. 검토 페이지의 동작은 가상 데이터이며 고객 정보·예약·결제 내역을 저장하지 않습니다.

## 10. 구현 순서와 완료 기준

1. **흐름 검토:** 이 문서·클릭 시안으로 신규 예약, 당일 미용, 미결제 완료, 결제, 재방문 시나리오를 확인.
2. **업무 뼈대:** 달력 → 날짜 목록 → 예약 → 방문 상세. 기존 고객·신규 고객 모두 한 흐름에서 예약.
3. **작업과 결제:** 독립 상태, 추가금 확인, 방문 사진, 결제 중복 방지, 실패 복구.
4. **가격표와 장부:** 고객 가격 안내·견적 공유, 실제 결제일 매출·운영비·차액.
5. **운영 기반:** 로그인·매장 구분·기기 간 저장·백업·복구와 사진 용량 관리. 실데이터 운영의 출시 조건.
6. **확장:** 직원별 일정, 예약금·환불, 공식 지원 범위를 확인한 네이버 연동.

완료는 버튼 개수가 아니라 다음 결과로 판단합니다. 재방문 고객을 재입력하지 않고 예약할 수 있음 / 미용 완료가 결제를 발생시키지 않음 / 고객 사진을 방문별로 다시 찾을 수 있음 / 가격표를 보호자에게 실제 전달할 수 있음 / 결제·운영비가 장부에 한 번만 반영됨 / 저장 실패와 취소에서 기록이 사라지지 않음.

## 11. 운영자와 확인할 결정

다음은 답이 없어서 구현을 막는 질문이 아니라, 검토 시 바꿀 수 있는 가정입니다.

1. 서비스 이름·기본가·체중 구간·견종 기준: 실제 매장 가격표를 기준으로 확정. 숫자는 시안용.
2. 연락처 없이 예약을 받아야 하는 경우가 있는가: 현재 시안은 보호자·반려견 이름을 우선, 연락처 필수 여부는 검토.
3. 입질·엉킴 추가금은 어떤 시점에 어떻게 보호자에게 확인받는가: 우선 안내 여부를 명시적으로 기록하는 안.
4. 결제는 보통 인계 시 한 번인가: 현재 기본안은 완료 후 결제. 선결제·예약금은 실제 필요 확인 후 별도 설계.
5. 별도로 판매하는 스파·관리 서비스가 실제 있는가: 없다면 기본 메뉴에 넣지 않음.


## 12. 매장 요금표 꾸미기

운영자가 로고·배경색·테두리를 선택해 매장 안내 이미지를 만드는 흐름을 추가합니다. **가격 안내표(P08) → 꾸미기(P09) → 미리보기 → 다운로드** 순서입니다. 새로운 최상위 메뉴로 늘리지 않고 가격표의 보조 동작으로 제공합니다.

- 매장 정보: 표시 이름·로고·연락처/안내 문구. 투명 PNG·JPG·WebP 로고를 비율 유지해 배치하고 제거·교체 가능.
- 스타일: 레퍼런스 기반 미용샵 핑크(기본), 따뜻한 크림, 차분한 세이지, 심플 화이트. 기본 스타일에서 시작해 배경색·포인트색을 변경.
- 주변 장식: 없음·단선·이중선·물결 테두리, 모서리 잎 장식 켜기/끄기. 장식은 텍스트 바깥 여백에 배치.
- 배치: 로고 크기와 가운데/왼쪽 정렬, 일러스트 선택. 배경에 맞춰 본문 글자색을 조정.
- 내용: 견종 분류 × 체중 행 × 서비스 열의 셀 가격, 열별 주석, 분류별 견종·중량 안내, 하단의 기타 추가금·고양이 미용. 내부 원가나 고객 개인 정보를 포함하지 않음.
- 출력: 폭 1800px의 내용 길이에 맞춘 세로 PNG(기본) 또는 A4 비율(1800×2546px) PNG. 촘촘한 표를 정사각형에 강제로 줄이지 않습니다. 미리보기와 저장 이미지는 같은 렌더링 결과를 사용.
- 긴 문구는 자동 줄바꿈하고 한 장에 넘치면 다운로드를 막아 내용을 줄이거나 비율을 변경하도록 안내. 서비스는 공통 열 6개, 견종 분류 최대 6개, 분류당 체중 행 최대 8개입니다.
- 디자인 초기화는 로고·가격 내용을 보존. 꾸미기와 다운로드가 예약·결제 금액을 수정하지 않음.

[실제 PNG 다운로드를 체험하는 꾸미기 시안](https://mahyuna.github.io/toy_diary/planning/pricelist.html)을 제공합니다. 시안은 샘플 가격을 화면 안에서 편집하며 실제 앱 데이터와 연결하지 않습니다. 요금 내용·로고·색·레이어 순서는 현재 브라우저에 자동 저장되고 새로고침 후 복원합니다. 전체 백업 JSON으로 다른 기기에 복원할 수 있습니다. 실제 앱 가격표·예약 데이터 연결과 서버를 통한 기기 간 동기화는 별도 범위입니다.


## 13. 레퍼런스 기반 표형 요금표

사용자 제공 이미지를 우선 디자인 기준으로 삼습니다. 연한 핑크 배경, 차콜 본문, 둥글고 두꺼운 제목, 작은 꽃 포인트, 얇은 가로선과 표 중심 구성이 기본입니다. 분류 제목·견종 설명·중량 안내·열별 주석·체중별 가격·하단 추가금까지 하나의 안내표에 보여줍니다. 브랜드 로고는 사용자가 직접 올립니다.

가격 모델은 ‘분류별로 독립적인 체중×서비스 셀’입니다. 각 서비스 가격을 일괄적인 기본가+추가금으로 추정해 만들지 않습니다. 체중 행·분류·가격 칸을 수정할 수 있으며 빈 칸은 ‘—’로 표시합니다. 분류별 초과체중 규칙은 현재 안내문으로만 표시하고 시안에서 자동 견적을 계산하지 않습니다. 실제 예약 요금과 연동하려면 체중 경계와 매장 분류 규칙을 먼저 확정해야 합니다. 과거 견적·결제 금액은 변경하지 않습니다.

국내 공개 사례와 직접 확인한 문장은 [조사 기록](RESEARCH.md)의 최신 절에 기재합니다.


## 14. 요금표 스튜디오 저장·편집

- 기본은 캔버스 보기. 요금표의 금액·제목·견종 설명·안내·서비스명 등을 누르면 해당 위치에 입력칸이 열림. 상단 캔버스/폼 탭으로 같은 데이터의 편집 방식을 전환. 폼은 섹션별 입력칸과 전체 디자인·매장 설정을 제공.
- 선택한 글자 요소 단위로 굵게·기울임·밑줄·색·크기·정렬 지정 및 서식 초기화. 한 문장 내 일부 글자에 서로 다른 서식을 적용하는 방식은 지원하지 않음.
- 선택 테두리의 이동 손잡이와 크기 손잡이로 텍스트·로고·표·섹션을 배치. 상위 선택으로 셀 → 표 → 섹션을 선택. 자동 정렬은 수동 배치를 지우고 기본 흐름으로 복원하며 되돌리기 가능. 이동·크기·서식은 브라우저 저장과 전체 백업 JSON에 포함.
- 선택 표시와 입력칸은 출력 이미지에 포함하지 않음. 모바일에서는 캔버스 우선 표시, 확대 버튼으로 작은 셀을 크게 편집.
- 입력 후 350ms에 현재 브라우저에 자동 저장. 창 숨김·종료 시에도 동기 저장을 시도. 새로고침 후 요금·로고·스타일·섹션/열 순서를 복원.
- 저장 공간 부족·접근 실패 시 자동 저장 성공으로 표시하지 않고 전체 백업 다운로드를 안내. 손상된 기존 저장값은 자동으로 덮어쓰지 않음.
- CSV 내보내기/불러오기: 분류·체중·서비스 칸, 별도 목록, 고양이·추가금·문구 섹션과 순서. UTF-8 BOM·줄바꿈·따옴표·쉼표 지원. 빈 셀과 0 구분. 로고·디자인은 CSV에 담지 않음.
- 전체 백업 JSON: 로고·모든 색·레이아웃·섹션/열 순서와 내용을 함께 복원. 잘못된 파일은 반영하지 않고 현재 문서를 유지.
- 사용자가 CSV 파일을 직접 선택하고 브라우저 권한을 허용한 경우 파일 자동 쓰기 제공. File System Access 미지원 브라우저는 브라우저 자동 저장과 CSV 다운로드 이용. 새로고침 후 파일 연결 권한은 다시 설정하며 브라우저 저장은 그대로 유지.
- 색: 배경·매장 제목·섹션 제목·본문/몸무게·가격·안내·표 선/테두리·꽃/모서리·서비스 열 제목을 각각 지정. 섹션별 제목·본문·가격·안내·선·배경·열 제목의 개별 색 우선 적용, 체크 해제 시 전체 색 상속.
- 바깥 테두리 종류·두께·여백, 섹션별 실선/점선/두께, 제목/본문/가격 크기와 간격 조절.
- 섹션과 서비스 열은 포인터 드래그 또는 이동 버튼으로 재정렬. 서비스 열 이동/삭제는 모든 견종표의 같은 가격 칸과 함께 처리.
- 견종 표/고양이/추가금 목록/설명 섹션을 자유롭게 추가하고 표시/숨김·순서·전체 폭/반폭을 지정. 견종 표는 가독성을 위해 전체 폭. 반폭 두 개가 연속되면 같은 줄에 배치.
- 되돌리기/다시 실행으로 최근 편집 복구. 저장은 이 기기의 브라우저에 한정되며 웹앱 서버 동기화나 영구 보관을 보장하지 않음. 다른 기기에서는 백업을 가져오기.

검증: `npm run test:studio`는 CSV 왕복·전체 백업·열 이동의 가격 보존·잘못된 파일 거부·캔버스 서식 검증·그룹과 하위 셀의 좌표 변환을 확인합니다. 브라우저에서 새로고침·다운로드·드래그·저장 실패를 별도로 확인합니다.

### 모바일 편집 흐름

- 첫 화면은 요금표와 캔버스/폼 전환, 하단 항목 찾기·전체 설정·PNG 저장으로 구성. 백업·CSV 등은 더보기에 배치.
- 요금표를 누르거나 항목 찾기에서 섹션과 항목을 고르면 하단 편집창 표시. 큰 입력창, 금액용 숫자 키보드, 이전/다음 칸으로 연속 입력. 값은 동일한 문서에 즉시 반영하고 자동 저장.
- 서식은 접힌 상세 도구에서 필요할 때 열기. 이동 손잡이는 위치·크기 조절 모드를 켰을 때만 표시해 스크롤 중 실수 방지.
- 폼에서는 섹션 선택을 상단에 두고 긴 섹션 관리 목록은 접어 둠. 편집창은 visualViewport 변화에 맞춰 키보드 위로 배치하고 내부 스크롤 허용.
- Chromium 모바일 터치 에뮬레이션에서 항목 찾기→연속 입력→서식→새로고침→폼 확인, 320/390px 화면과 데스크톱 전환 검증. 실제 iOS/Android 키보드 실기기 검증은 별도 필요.

### 캔버스 추가와 전환

- 캔버스 오른쪽 아래 ＋ 추가 및 모바일 편집창의 ＋ 추가에서 몸무게 행·목록 줄·서비스 열·새 섹션 생성. 추가 대상 섹션을 메뉴에서 변경 가능. 선택한 몸무게 행이 있으면 바로 아래 삽입, 없으면 마지막에 추가. 기존 가격을 유지하고 새 항목을 선택해 즉시 입력.
- 서비스 열은 모든 견종표에 함께 추가되며 최대 8열, 몸무게 30행, 목록 40줄, 섹션 24개 한도를 동일하게 적용. 기존 자동 저장·되돌리기를 사용.
- 편집창·추가 메뉴 열림/닫힘, 다음 칸 전환, 보기 전환에 짧은 모션 적용. 동작 줄이기 환경에서는 애니메이션 생략. 빠른 중복 추가 입력 차단.

### A4 여러 페이지

- 내용에 맞춘 긴 이미지와 A4 자동 페이지를 선택. A4는 섹션을 우선 통째로 다음 장에 배치하고, 한 장보다 긴 표·목록은 행/항목 사이에서 나눔. 긴 안내 내용은 문단 경계를 우선하여 분할.
- 페이지마다 매장명·제목·안내를 표시하고, 나뉜 표에는 섹션 제목과 서비스 열 머리글을 반복. 행/목록 ID를 보존해 각 장에서도 원래 데이터를 편집. 긴 문구의 편집창에서는 원문 전체를 수정.
- 이전/다음 페이지로 확인, 현재 장 PNG 또는 전체 PNG ZIP 저장. 각 장 1800×2546px의 A4 비율. 긴 이미지로 되돌려도 원본 내용을 유지. 제목/안내 또는 수동 배치된 단일 항목 자체가 한 장을 넘으면 내용을 자르지 않고 조정 안내 표시.
- 자동 테스트: 긴 표의 모든 행·가격 보존, 분할 목록의 원본 인덱스 보존, 페이지 높이·머리글 반복, ZIP 무결성과 각 PNG의 미리보기 바이트 일치, 출력 형식 저장 확인.
