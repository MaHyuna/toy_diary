# 사장님·보호자 접근 권한

기준일: 2026-11-05. **주소를 나누는 것만으로 권한이 생기지 않는다.** 사장님 화면을 숨겨도 API에 직접 요청할 수 있으므로 서버가 모든 관리 API의 세션을 검사한다. 보호자 링크는 해당 아이의 공개 기록을 읽는 제한된 권한이며 사장님 세션과 다르다.

## 권한표

| 사용자 | 허용 | 허용하지 않음 |
| --- | --- | --- |
| 익명 방문자 | 공개 요금·예약 가능 시간 조회, 예약 신청 제출, 로그인 상태 확인 | 전체 예약·고객·연락처·장부·미공개 케어 기록 조회, 예약 확정·수정·정산 |
| 유효한 케어 링크를 가진 보호자 | 해당 공개본과 같은 아이의 공개된 방문 이력 읽기 | 미공개 초안, 다른 아이, 보호자 연락처·금액·내부 메모, 작성·수정·공개·해제 |
| 로그인한 사장님 | 매장 예약·고객·정산·요금·미용 기록 관리, 공개·해제 | 미구현 직원별·다중 매장 권한을 가진 것으로 간주하지 않음 |

보호자 케어 링크는 암호학적 난수 토큰을 가진 사람에게 조회를 허용하는 방식이다. 보호자 계정 로그인이나 본인 확인이 아니며 링크를 전달받은 사람도 열 수 있다. 공개 해제는 토큰을 폐기한다. 이미 저장·전달한 파일과 화면 캡처는 회수하지 못한다. 공개 스냅샷·재발행·파일 전달의 범위는 [케어 기록 흐름](CARE_FLOW.md)을 참고한다.

## 서버가 검사하는 경계

관리 API는 유효한 사장님 세션을 요구한다. `/api/state`, 고객·반려동물 정보, 예약·정산·지출·요금 관리, 예약 신청 목록·승인, 케어 초안·공개·해제도 포함한다. `/api/public/`이라는 접두사만 보고 모두 공개하지 않는다. 로그인 없이 허용하는 업무 API는 다음 **메서드와 경로의 조합**으로 한정한다.

| 메서드 | 경로 | 범위 |
| --- | --- | --- |
| GET | `/api/public/catalog` | 공개 예약·요금 기준 |
| GET | `/api/public/availability` | 예약 가능한 시간 |
| POST | `/api/public/requests` | 고객 예약 신청 제출 |
| GET | `/api/public/care/<token>` | 유효한 토큰의 공개 케어 조회 |

인증용 예외는 `GET /api/auth/session`, `POST /api/auth/login`, `POST /api/auth/logout`이다. 로그인 요청 JSON은 `{"password":"..."}`이며 실제 비밀번호는 화면에서 입력한다. 관리 데이터를 포함하지 않는 세션 상태 응답으로 로그인 여부·설정 여부를 확인한다. `/api/health`도 관리 세션을 요구한다.

사장님 비밀번호가 설정되지 않으면 관리 API와 로그인은 `503`으로 닫힌다. 빈 비밀번호나 기본 비밀번호로 우회하지 않는다. 설정된 서버에서 세션이 없거나 만료되면 관리 API는 `401`을 반환한다. 비밀번호가 틀리면 `401`, 반복 실패 제한에 걸리면 `429`, 다른 사이트에서의 변경 요청은 `403`으로 거절한다. 서버 오류나 `503`을 로그인이 성공한 것처럼 처리하지 않는다.

## 사장님 세션

- 서버가 발급하는 난수 세션을 `mongle_owner_session` 쿠키로 보관한다. 쿠키는 `HttpOnly`, `SameSite=Strict`, 경로 `/`를 사용한다. 프런트엔드 저장소의 역할 값이나 주소 파라미터를 인증 근거로 쓰지 않는다.
- 세션 유효기간은 로그인 후 8시간이다. 로그아웃은 서버 세션을 폐기하고 쿠키도 만료시킨다. 서버 재시작 시 메모리에 있던 세션이 무효가 되어 다시 로그인해야 한다.
- 서버는 원문 세션 토큰 대신 해시와 만료 시각을 보관한다. 비밀번호와 세션을 URL·로그·화면 안내에 출력하지 않는다.
- JSON 변경 요청의 출처를 확인하고 다른 사이트에서 보낸 요청을 거절한다. 쿠키 설정이나 로그인 화면만으로 모든 변경 요청 검사가 대체되는 것은 아니다.

## 서버 실행 설정

Python 서버는 셸 환경변수를 읽는다. **`.env` 파일을 자동으로 읽지 않는다.** 아래 값은 설명용 자리표시자이며 실제 사용할 비밀번호로 바꿔 서버 프로세스에 전달한다. 실제 비밀번호를 README·소스·URL·명령 출력에 기록하지 않는다.

```bash
export MONGLE_OWNER_PASSWORD='CHANGE_THIS_TO_A_PRIVATE_PASSWORD'
python -m server.app --host 127.0.0.1 --port 3000
```

프런트엔드는 먼저 `npm ci`와 `npm run build`로 빌드한다. 실행 후 `/owner/`에서 설정한 비밀번호로 로그인한다. 비밀번호를 바꾸거나 세션을 모두 끊으려면 환경변수를 변경하고 서버를 재시작한다. 현재는 단일 사장님 비밀번호 방식으로, 비밀번호 재설정 메일·직원 계정·계정별 권한은 제공하지 않는다.

HTTPS 프록시 뒤에서 운영할 때는 서버 프로세스에 다음을 함께 설정한다.

```bash
export MONGLE_SECURE_COOKIES=true
```

이 설정은 세션 쿠키에 `Secure`를 붙이고 HTTPS 출처를 기대하게 한다. TLS를 설정하거나 HTTP를 암호화하는 명령은 아니다. 프록시에서 실제 HTTPS와 원래 호스트 전달을 구성해야 한다. `X-Forwarded-Proto` 같은 외부 요청 헤더만 신뢰해 HTTPS로 판단하지 않는다. 로컬 일반 HTTP 개발 서버에 이 값을 켜면 브라우저가 보안 쿠키를 보내지 못해 로그인 상태를 유지하지 못할 수 있다.

로그인 구현이 HTTPS 배포·서버 접근 제한·데이터 백업을 대신하지 않는다. 여러 매장·여러 운영자를 위한 데이터 격리나 고객 계정 로그인까지 제공한다고 안내하지 않는다.

## 화면 경로

| 경로 | 목적 |
| --- | --- |
| `/owner/` | 로그인한 사장님의 관리 화면 |
| `/customer/booking/` | 고객 예약 신청 |
| `/customer/prices/` | 고객 요금 안내 |
| `/customer/care/?token=...` | 보호자용 공개 케어 기록 |

호스팅이 프로젝트 하위 경로를 쓰면 해당 기준 경로가 앞에 붙는다. 기존 `?screen=owner`, `?screen=booking`, `?screen=prices`, `?screen=care&token=...` 링크도 호환한다. 고객 화면에는 관리자 진입 링크를 노출하지 않는다. 고객이 `/owner/` 주소를 알거나 직접 입력해도 서버 데이터 접근은 사장님 세션이 있어야 가능하다.

## GitHub Pages 체험판

Pages는 정적 화면이므로 위 서버 세션 인증을 실행할 수 없다. **`예시 데이터로 사장님 체험`은 역할 미리보기 진입 버튼**이며 실제 사장님 로그인이나 권한 통제가 아니다. 더미 비밀번호를 받아 인증처럼 보이게 하지 않는다. 체험 진입 여부는 현재 브라우저 탭의 `sessionStorage`에 두며 관리 권한을 보장하지 않는다.

체험 데이터는 현재 브라우저에 저장된다. 다른 기기와 동기화되지 않으며, 같은 브라우저 저장소의 데이터는 역할 화면 구분으로 보호되지 않는다. 실제 고객 정보는 입력하지 않는다. Pages에서 서버 비밀번호를 입력하도록 요구하거나 프런트엔드에 비밀번호를 배포하지 않는다.

OAuth·휴대전화 본인 확인, 보호자 계정별 반려동물 소유 확인, 다중 기기 계정 동기화, 직원별 권한, 다중 매장 격리는 이후 범위다. 이번 보호자 권한은 공개 토큰 읽기로 한정한다.
